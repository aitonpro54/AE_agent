# Сверка плейсхолдеров после сбоя запуска

При timeout, `verification_required`, частичной ошибке setter или недостаточном
read-back сначала сверить фактическое состояние. Этот рецепт выполняет чтение.

1. Сохранить `run.id`, исходную ошибку и outcome запуска. `execution`, `mutation`
   и `verification` независимы: применённый setter с не завершённой проверкой
   нельзя считать не выполненным.
2. Вызвать `reconcile_plan_run({runId})` или кнопку CEP «Сверить результат».
   Сервер берёт исходный план, IDs, параметры и command lifecycle из сохранённой
   записи. Клиентский новый план или snapshot не являются доказательством.
3. Проверить каждый шаг. `applied` означает, что текущие ожидаемые значения
   подтверждены независимым чтением. Для потерянного ответа это подтверждение
   текущего состояния, а не исторического receipt вызова. `not_applied` требует
   доказанного отказа до отправки; несовпадающее значение само по себе даёт
   `unknown`, поскольку возможны частичная запись или последующая ручная правка.
4. Не повторять applied/unknown шаги. Отсутствующая/повреждённая запись,
   сменившийся проект, неоднозначные ID, unsupported operation и неполное чтение
   оставляют результат неизвестным. При необходимости продолжить подготовить
   отдельный обычный proposal только для проверенной оставшейся работы, сохраняя
   принятые правки и все confirmation/checkpoint gates.
5. Для свойств использовать `get_property_value` по comp/layer IDs и точному
   composite `propertyPath`, при keyframe — по нужному `time`. Проверить source,
   timing и transform адресным `get_layer_details`/`verify_placeholder_read_back`.
   Смена project/layer indices — диагностический адресный drift; identity
   свойства/эффекта с его propertyIndex/name/matchName остаётся строгой.

Сверка не вызывает retry, repair, сохранение проекта или откат. Исходная ошибка
остаётся в результате запуска. Artistic acceptance по изображениям проводится
отдельно, даже если технический read-back прошёл.
