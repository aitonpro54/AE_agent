# Add Background Layer Typed Plan

## Goal

Добавить безопасный generated full-comp background layer в композицию через existing typed bridge tools.

## Applies When

- Пользователь просит добавить background layer, color background, generated backdrop, full-frame rectangle, or solid-looking background behind generated artwork.
- Допустима safe adaptation: generated shape layer that covers the composition frame, styled with `ADBE Fill`, with typed read-back.
- Target comp is either newly generated by the plan with explicit comp settings, or an explicit comp target that is read back before background creation.
- If the user needs persistent expression-driven auto-resize, exact `moveToEnd` behavior behind arbitrary existing user layers, or native background-layer stack management, fail closed and request a separate typed-tool contract.
- Задача не требует raw script execution, deleting existing layers, source relinking, render queue changes, or broad template batch updates.

## Plan Pattern

1. Establish the target composition. Run `create_comp` only when the user requests a new generated comp; otherwise require an explicit target comp identity and read it with `get_comp_details`.
2. Use target comp width, height and duration from `create_comp` output or `get_comp_details` read-back.
3. Run `create_shape_layer` for a generated rectangle background layer with `size:[width,height]`, `position:[width/2,height/2]`, `startTime:0`, full comp duration, a clear generated prefix, and non-destructive placement.
4. Use `add_effect` with `ADBE Fill` on the generated background layer when the requested background color must be represented as effect evidence.
5. When the workflow creates generated foreground proof artwork, create it after the background so `get_comp_details` read-back can prove the generated background sits behind the generated foreground.
6. Include `verifyAfter:true` and a stable `idempotencyKeyTemplate` on each mutating create/effect step.
7. Run `get_comp_details` with layer read-back for the same comp.
8. Run `get_layer_details` for the generated background layer to confirm size, position and `ADBE Fill` evidence when available.

## Safety Gates

- Mutating composition workflow.
- Requires validated Agent plan, dry-run, explicit confirmation, `allowMutations:true`, idempotency and post-mutation read-back.
- Use checkpoint or edit-session protection for confirmed live runs.
- Use generated-prefix layer names and never delete, rename, relink or reorder existing user layers as part of this recipe.
- Do not promise persistent expression-driven auto-resize, exact `moveToEnd` behavior against arbitrary existing user layers, or native background-layer stack management; fail closed when those semantics are required.
- Do not use this recipe for template batch changes, masks, expressions, source relinking, render queue changes, existing layer cleanup or raw ExtendScript.

## Verification

- The plan creates or targets exactly one comp and adds one generated full-comp background shape layer.
- `get_comp_details` read-back shows the generated background layer in the target comp with the expected generated name and no unexpected changes to user layers.
- `get_layer_details` or effect read-back shows expected rectangle size, center position and `ADBE Fill` on the generated background layer when color styling is requested.
- For generated proof artwork, read-back shows the generated background behind the generated foreground layer.
- The plan contains only optional comp creation, generated shape-layer background creation, optional fill-effect styling, optional generated foreground proof, and typed read-back steps.
- Exact source JSX semantics for expression-driven resize, arbitrary existing-layer `moveToEnd`, or persistent background stack management are reported as a typed-tool gap.
