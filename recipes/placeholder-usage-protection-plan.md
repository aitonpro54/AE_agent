# Интервалы, группы и принятые плейсхолдеры

Применять при заполнении набора плейсхолдеров без повторяющихся фрагментов,
с разными подтверждёнными группами или исполнителями и сохранением ручных правок.

1. Прочитать `get_placeholder_protection` и `get_placeholder_usage` для явных
   корневых композиций. Сервер строит карту из свежего ограниченного inventory:
   источник, sourceRange, rootRange, маршрут вложенности и устойчивые ID цели.
2. В CEP подтвердить группу исходника; имя файла не является доказательством.
   Для выделенного набора включить разные группы и запрет повторов по задаче.
3. Передать точные назначения в `check_placeholder_assignments`. Проверяются
   уже занятые и предлагаемые интервалы одного медиа, включая повторные импорты.
   Соседство `[0,5)` и `[5,8)` допустимо; любое реальное пересечение отклоняется.
4. Построить `build_placeholder_plan` по свежим ID, маршруту и диапазонам;
   сохранить встроенное expectedReadBack при создании proposal. Проверки
   proposal, каждого шага и AE-side preconditions сохраняют принятую правку.
5. Выполнить обычный dry-run/confirmation/checkpoint flow. Прочитать цель заново
   и вызвать `verify_placeholder_read_back`; индекс является адресной подсказкой.
6. После ручной проверки выбрать «Принять выбранный плейсхолдер». Источник,
   время и transform фиксируются; checkbox добавляет выделенные статические
   свойства оформления. Снятие защиты — отдельное действие пользователя в CEP.

Неполная карта, неизвестная группа, stretch/time remap, повторное вхождение
общего плейсхолдера, анимация защищаемых свойств и конфликт accepted snapshot
дают явный отказ. Unsaved проект не принимается в постоянную память; рецепт
не сохраняет AEP ради идентичности. Память разделена по сохранённым проектам;
corrupt state блокирует изменения, а модель не может подменить снимок или
передать флаг снятия защиты.

Сопоставление файлов лексическое; неявные symlink aliases не доказаны. Проверки
offline helper/JSX VM/isolated daemon не являются live или художественной приёмкой.
