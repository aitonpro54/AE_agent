# Add Posterize Time Adjustment Layer Typed Plan

## Goal

Добавить безопасный Posterize Time adjustment layer в композицию через existing typed bridge tools.

## Applies When

- Пользователь просит добавить Posterize Time adjustment layer, posterized motion look, stepped-time effect, low frame-rate motion effect, or stop-motion timing look over a composition.
- Допустима safe adaptation: generated adjustment layer covering the target comp, with `ADBE Posterize Time` applied through typed effect tools and typed read-back.
- Target comp is either newly generated by the plan with explicit comp settings, or an explicit existing comp target that is read back before the adjustment layer is added.
- If the user needs actual comp frame-rate changes, time-remapping keyframes, nested precomp retiming, per-layer timing edits, or exact source stack/index behavior, fail closed and request a separate typed-tool contract.
- Задача не требует deleting existing layers, changing existing artwork, render queue changes, template batch updates, or arbitrary script execution.

## Plan Pattern

1. Establish the target composition. Run `create_comp` only when the user requests a new generated comp; otherwise run `get_active_comp` or `get_comp_details` to verify the explicit target comp before mutation.
2. Use target comp duration, width, height and pixel aspect from `create_comp` output or `get_comp_details` read-back.
3. Run `create_adjustment_layer` with a generated-prefix layer name, full comp dimensions, `startTime:0`, and comp duration so the returned layer read-back can prove `adjustmentLayer:true`.
4. Run `add_effect` on the generated adjustment layer with matchName `ADBE Posterize Time`.
5. Run `get_effect_details` with property read-back before setting a requested posterize frame rate.
6. Run `set_effect_property` only after `get_effect_details` identifies the exact frame-rate property for the Posterize Time effect; fail closed when the property cannot be identified safely.
7. Include `verifyAfter:true` and a stable `idempotencyKeyTemplate` on each mutating create/effect/property step.
8. Run `get_comp_details` with layer read-back for the same comp.
9. Run `get_layer_details` and final `get_effect_details` for the generated adjustment layer to confirm `adjustmentLayer:true`, `ADBE Posterize Time`, and the frame-rate property value when one was requested.

## Safety Gates

- Mutating composition workflow.
- Requires validated Agent plan, dry-run, explicit confirmation, `allowMutations:true`, idempotency and post-mutation read-back.
- Use checkpoint or edit-session protection for confirmed live runs.
- Use generated-prefix layer names and never delete, rename, relink or reorder existing user layers as part of this recipe.
- Do not promise comp frame-rate mutation, time-remapping, per-layer retiming, exact source stack/index placement, or nested precomp timing changes; fail closed when those semantics are required.
- Do not use this recipe for render queue changes, expression edits, source relinking, template batch changes, existing layer cleanup or broad composition mutation.

## Verification

- The plan creates or targets exactly one comp and adds one generated adjustment layer.
- `get_layer_details` read-back shows the generated layer with `adjustmentLayer:true` in the expected comp.
- `get_effect_details` read-back shows `ADBE Posterize Time` on the generated adjustment layer.
- If the user requested a frame rate, the plan shows the exact frame-rate property evidence before `set_effect_property`, then reads back the same frame-rate property after mutation.
- `get_comp_details` read-back shows no unexpected changes to existing user layers.
- Exact source JSX semantics for comp frame-rate changes, time-remapping, per-layer retiming or arbitrary stack placement are reported as typed-tool gaps.
