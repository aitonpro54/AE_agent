## Порядок следующих блоков

1. **Принять фактический результат соседа.** Зафиксировать commit, изменения Origin/подключения, установленные identities, команды и реальные результаты. Известная на начало подготовки проблема — `cep_origin_required`; сосед продолжает её диагностику. Не перепроверять неизменённые suites без причины.
2. **При необходимости выбрать один ограниченный Argon review.** Выбрать один предмет по текущему этапу: план/контракт либо существенный integration result либо конкретный сложный блокер. Это один пакет, не цепочка plan-review → result-review. Только frozen snapshot/allowlist, request+manifest hashes и точные evidence gaps.
3. **Разобрать findings и закрыть их локальными evidence.** По каждому замечанию использовать адресное воспроизведение или достаточный source evidence; внести минимальную подтверждённую правку в разрешённом scope и выполнить целевую локальную техническую проверку. Неподтверждённое/устаревшее замечание записать с доказательством. Повторный Argon review после fixes не обязателен и возможен только по новому явному поручению пользователя.
4. **Завершить разрешённую установку и приёмку.** Exact source/package/install/Node/CEP bindings, configured MCP handshake/status, реальная read-only инспекция через installed IPC. Для текущей text-цели сохраняются fresh native confirmation, ownership/revisions, checkpoint, single setter и read-back. Не менять пользовательский AEP, не выполнять raw/save/destructive и не перезапускать AE ради удобства. Прежние специальные разрешения проверять по исходному scope и свежему состоянию.
5. **Подвести выбранный состав к выпуску.** Сверить открытые критерии плана, документацию и восстановление локальными техническими evidence. Итоговое Argon review не является условием выпуска. Полная release-проверка остаётся отдельным явным действием по AGENTS.md: общий mandate не записывать как уже выполненный release run. Публикация/push/PR, платный API, grants или обход защит этим планом не поручаются.

Если требуемое физическое действие остаётся за человеком, подготовить весь независимый конкретный результат и запросить только это действие с точной причиной. Неполную живую приёмку не объявлять успехом, продолжая доступную независимую работу.
