## Предлагаемое направление: M2b, offline-контракт lifecycle и grant

Цель следующего инженерного блока — определить и проверить границу доверенного embedding, которая впоследствии сможет принимать авторитетные события проекта и подтверждения. Проверка выполняется на явно synthetic event source. Она не доказывает существование такого источника в AE и не делает production connect доступным.

Перед кодом уточнить контракт и соответствие существующим seams; не вводить отдельную универсальную систему capabilities без доказанной необходимости. Возможные адресные изменения: `core4/core/authority.js`, потребляющие участки `core4/core/broker.js`, отдельные offline fixtures/tests, packaging и validation map по фактическому diff. Точные новые файлы и API определяются после выбора этого направления.

Критерии предлагаемого среза:

| ID | Проверяемое поведение |
| --- | --- |
| C1 | Startup без event source/issuer остаётся доступен для status, а production connect/mutation — unavailable. Публичный MCP не получает выдачу lifecycle proof или grants |
| C2 | Synthetic new/open/revert/replacement меняют project-incarnation epoch даже при том же пути и item/layer IDs; неопределённая последовательность событий закрывает admission |
| C3 | Потеря непрерывности источника, его restart или reconnect сами по себе не подтверждают прежний проект. Channel/controller/store epochs не подменяют project epoch |
| C4 | Подтверждение относится к конкретному server-owned proposal и его эффекту/целям; отзыв, смена проекта и drift требуют повторной проверки перед send. Ownership/checkpoint gates сохраняются |
| C5 | Reset, потеря источника или отзыв запрещают новые отправки, но не стирают уже отправленный receipt, UNKNOWN и fences |
| C6 | Scoped validation честно выбирает реальные consumers; чужие module pins не обновляются без изменения их байтов/контрактов. Результат явно offline, releaseCertified=false |

Вне этого предложения: реальные AE hooks/наблюдатель, UI подтверждений, production issuer/listener/bootstrap, установленный CEP/MCP, actual shared-lane takeover, census живого runtime, save/reopen, Codeburn, cutover и публикация. Не повторять ранее остановленный дополнительный сетевой probe под другим инструментом или исполнителем.
