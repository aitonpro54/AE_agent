## Текущий локальный вердикт, который надо критически проверить

Core сохраняется единой точкой входа, владельцем server-side допуска, очереди, журнала и типизированных операций. Нужно компоновать повторно используемые primitives, а не создавать пакет под каждую единичную художественную задачу. Не требуется переписывать весь AE DOM. При этом typed contracts и инварианты существующих модулей сохраняют ценность.

Принято твоё возражение против порядка «сначала весь Core-only workflow, потом сравнительный анализ». Новый порядок: общие P0 readiness/outcomes/reset/exact targets; ранняя ограниченная проверка native/перенесённого примитива против частного Kumo adapter на одном контракте; расширение и поставка выбранного пути только после сравнения. Большой save/lifecycle имеет самостоятельные ограничения и проверки, не должен скрыто исчезнуть из обещанной готовности.

Не принято безусловное утверждение, что адаптер Kumo тонкий/дешёвый. Вызвать команду легко, установить её durable outcome после ACK loss/owner restart и исключить конкурирующую/старую выдачу сложнее. Если интеграция требует большой переделки транспорта либо неизвестный исход не устанавливается, предпочесть native или заимствованный MIT/legacy-примитив внутри Core. Встроенный код не требует отдельного Kumo MCP и отличается по runtime boundary от внешнего backend. Kumo может стать полезным private backend только за измеримую пользу при необходимых гарантиях. Два прямых MCP writers в одном AE отвергнуты; разные AE процессы/рабочие копии допустимы как отдельная схема.

## Возражения к прошлому ревью: проверь их по коду

- COMPLETED_FAILURE может оставлять partial mutation; неизвестной бывает и запись PNG/verify. Чистый read timeout не должен автоматически требовать закрытия AE, но старая выдача должна быть доказанно завершена или погашена. delivered marker до HTTP reply не равен native begin. Ping не отменяет queued old request.
- Mutex, epoch, stopOnError, undo group и тег в comment полезны, но сами по себе не дают exactly-once/атомарности. Сбой возможен после duplicate и до тега. Именование слоя может быть пользовательским содержимым.
- Pull queue, не использующая push busy lock, не обязательно дефект. Нужен доказанный конфликт одинакового ресурса и анализ всех активных путей. Запретить альтернативную выдачу одной инструкцией модели недостаточно.
- Только local-comp expression scan, visible-layer digest или один PNG не покрывают cross-comp/name/index/dynamic references, matte/parent и shared uses. Lifecycle baseline нельзя без доказательства заменить digest одной comp.
- OS modal scan помогает, но между проверкой и dispatch состояние меняется. Отсутствие обнаруженного диалога не равнозначно успешной проверке native-ready.
- Общий запрос на монтаж не означает автоматический save-in-place/kill. Смысловое разрешение может пережить restart, но bindings/baseline/technical grants проверяются заново. Save-as может поменять активный путь.
- Заявленные ранее O(1), 200/500 ms, три секунды, пять–десять секунд и оценка девяноста процентов проектов не измерены. Их нельзя выдавать за доказательства или утверждённые SLA.
