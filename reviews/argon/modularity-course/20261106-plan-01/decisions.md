## Гипотезы и ограничения

H1 подтверждена частично: point-layout/text-layer действительно строят пакет и используют manual-http-runtime. Однако text-variant тоже вызывает buildPackage для двух композиций в test/text-variant.test.js:120–125; рекомендация считать его полностью изолированным эталоном слишком сильна. Узкий dependency list в map:1313–1316 не включает все файлы, читаемые сборщиком. Нужен разбор влияния этих файлов на конкретные assertions до автоматического reuse; фактический ошибочный PASS здесь не воспроизводился.

H2: manual-policy.js:5–8 действительно сводит selected/layout/additional в общий массив profiles. Унификация входа выглядит возможной, но эквивалентность reservation, receipt v1/v2 и recovery тестами в этом блоке не доказывалась.

H3: встроенного cache lookup в --run нет. Исторические manifest/evidence фиксируют ручной reuse; существование универсального внешнего cache runner не установлено.

Дополнение владельца анализа: products/titles закрепляет MODULE_PIN и CONTRACT_HASH, а автоматический Git diff селектора ограничен core4. Нужен явный маршрут проверки совместимости затронутого продукта; общий успех Core его не заменяет.

Предупреждение Argon о path traversal относится к будущему обобщению host guard. Наличие текущей уязвимости этим ревью не установлено. Аналогично требование <1 секунды для cache — пожелание, не подтверждённый SLA. Нулевые литералы названий модулей сами по себе не доказывают независимость: нужен сквозной пилот.

## Принятая рекомендация

Сохранить Core 4 и продуктовую границу. Перед дальнейшим расширением общего runtime провести небольшой пилот на одной capability: исходный замер → разделение proof/host guards и регистрация через проверяемый состав → реальные минимальные fixtures плюс отдельная package integration → повторный замер и product compatibility. Затем оценить автоматизацию reuse. Полные проверки lifecycle, integrity и recovery остаются по затронутым границам. Переносимость MSI/desktop входит в готовность изменённого модуля по постоянному контракту проекта.

Сначала переделывать всю тестовую инфраструктуру не рекомендуется. Узкие независимые улучшения фикстур не запрещены, если их результат не зависит от нового контракта. Переписывание Broker, универсальные hot-swap плагины, 3D derive и AME не входят в этот этап модульности.
