## Architecture

- `mcp-server\bridge-daemon.js`
  - Persistent local HTTP daemon.
  - Owns `127.0.0.1:3456`, CEP queue, command IDs, results, logs, backups, and `/tools` endpoints.
- `mcp-server\mcp-adapter.js`
  - Thin stdio MCP adapter for Codex.
  - Exposes tools and forwards calls to daemon HTTP endpoints.
  - Auto-starts `bridge-daemon.js` detached if `3456` is empty.
- `cep-panel\`
  - After Effects CEP panel.
  - Polls `/bridge/next`, executes ExtendScript via `evalScript`, posts `/bridge/result`.
  - Auto-connects after the user has connected once.

Do not use Windows logon startup as the normal lifecycle. The chosen default is:

1. User opens Codex and After Effects.
2. Codex MCP adapter starts.
3. Adapter starts daemon in the background if needed.
4. CEP panel connects/reconnects to daemon.

## Cautions

- Do not re-enable Windows logon startup unless the user explicitly chooses that tradeoff.
- Do not enable CEP Node/mixed-context for panel-side daemon start without explicit security approval.
- Do not change `/bridge/next` or `/bridge/result`; the CEP panel depends on these stable endpoints.
- Before large AE-changing tests, use `backup_project_file` on saved projects.
- Keep generated logs, backups, and snapshot zips out of git except intentional release archives already ignored by `.gitignore`.
