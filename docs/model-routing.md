# Маршрутизация AE Agent

Обновлено 3 октября 2026 года. Пользователь свободно выбирает любую доступную
модель и effort в UI/CLI. Проектный `.codex/config.toml` не задаёт model/effort
для чата или общий default модели субагентов. Доступные варианты определяет клиент.
Выбранная модель ведёт чат и контролирует результаты делегирования.

**Sol 6.1 / High** — рекомендация для диспетчеризации. Таблица ниже определяет
автоматический выбор исполнителей, если пользователь не указал другого.
Пример явного выбора Sol в CLI; можно выбрать другую доступную модель/effort:

```powershell
codex -C C:\Users\Ant\Documents\Codex\AE_agent -m gpt-6.1-sol -c 'model_reasoning_effort="high"'
```

Sol 6.1 рекомендован для контроля качества и сложной координации: официальный
[каталог Codex](https://learn.chatgpt.com/docs/models) рекомендует его для сложных
задач с инструментами; Luna предназначена для понятных повторяемых поручений.
Luna/high используется для простых самостоятельных поручений, когда их объём
или независимость оправдывают отдельного исполнителя. Один короткий вызов
диспетчер выполняет сам; средние задачи остаются у Flash под контролем модели чата.

Модель и effort конкретной именованной роли закреплены в `~/.codex/agents/*.toml`;
это настройки исполнителя при вызове роли, а не ограничение селектора чата.
`ae_specialist` — Sol 6.1/xhigh; `ae_architect` — Sol 6.1/ultra;
`ae_escalation` — Astra/high. Scout/operator — Luna/high, reviewer — Sol 6.1/high.
Наличие TOML само по себе не запускает агента; самостоятельные routine blocks
обязаны следовать маршруту из `docs/routine-dispatch-policy.md`. Исключение одного
короткого вызова не распространяется на серии; причина исключения фиксируется.
Глобальный
`model_context_window = 500000` и `model_auto_compact_token_limit = 425000`
действуют для обычных сессий и вызовов; профили Astra и media задают ту же пару.
`ae_scout` и `ae_operator` переопределяют его на 272000 токенов — текущее
штатное окно Luna в каталоге Codex. Общий `luna-standard` задаёт те же
272000 токенов и effort high при явном выборе этой роли для задач вне AE; он не заменяет
AE-ограничения `ae_scout`/`ae_operator`. Все три роли Luna задают собственный
`model_auto_compact_token_limit = 230000`, остальные роли наследуют 425000.
После обновления каталога сверяйте
штатное значение и TOML ролей.
Изменённые файлы применяются к новым загрузкам конфигурации/ролей; runtime
текущего чата не обновляется редактированием TOML. Если клиент ещё показывает
старую роль, используйте поддерживаемый явный model/effort либо новую загрузку
клиента; не вызывайте старую Astra-роль как будто она уже стала Sol.

## Обязательная диспетчеризация блоков

Маршрутизируй каждый самостоятельный блок и повторяй выбор после сложного
блокера согласно [политике диспетчеризации](routine-dispatch-policy.md).
Bounded поручения по умолчанию используют `fork_turns: none`, явный scope,
контекст и приёмку; полный history нужен только при обоснованной зависимости.
Выбранная модель чата сама по себе не является override. Это обязательные
инструкции, а не программный перехватчик tool calls; один smoke не доказывает
гарантированное назначение исполнителя.

## Выбор исполнителя

| Задача | Исполнитель |
|---|---|
| Пользователь указал модель/роль | Указанный поддерживаемый исполнитель |
| Статус, один готовый короткий вызов проверки или правки | Диспетчер сам |
| Простое самостоятельное поручение: поиск, извлечение данных, правка по образцу | Luna/high: `ae_scout` для чтения, `ae_operator` для правки |
| Большинство задач средней сложности с понятным scope и приёмкой | Flash 3.8/high через agy; контроль выбранной модели чата |
| Узкий сложный инженерный блокер | `ae_specialist`: Sol 6.1/xhigh |
| Архитектура, системные границы, сложное планирование | `ae_architect`: Sol 6.1/ultra |
| Очень сложная задача после содержательной неудачи Sol 6.1/ultra | `ae_escalation`: Astra/high |

Это постоянное разрешение пользователя на Flash для средних задач AE Agent,
а не требование спрашивать заново перед каждым запуском. Глобальный `AGENTS.md`
и `antigravity-cli` содержат то же исключение для этого проекта. VideoScout имеет
свой отдельный маршрут; в прочих проектах требуется прямое поручение/вызов skill. Настройка
маршрута сама по себе не запускает Flash и не даёт разрешения на новые live операции.

Диспетчер передаёт Flash законченную задачу и не реализует её параллельно. Flash
самостоятельно читает материалы, планирует и исправляет. Модель чата проверяет критерии,
diff, артефакты и применимые проверки без повторного полного аудита. До двух
содержательных исправлений одного проваленного критерия; затем локальный блокер
передаётся Sol/xhigh, системный — Sol/ultra. Обязательной цепочки моделей нет.
Чтобы вызвать Astra, приложите попытку Sol/ultra, проверенные гипотезы и оставшийся
пробел; одна трудная задача или ошибка доступа этого условия не выполняют.
Auth, quota, сеть, MCP, permissions и неизвестный исход операции сначала
диагностируются отдельно. Каждая смена исполнителя имеет записанную причину.

Luna получает точный scope и ожидаемый результат. Она может искать файлы/поля,
извлекать данные, классифицировать или править по ясному образцу; при неоднозначности
возвращает вопрос Sol без самостоятельного расширения scope. Live AE/UI ей
доступны только при отдельной передаче единоличного контроля и действующих gates.

Ultra — режим Codex с использованием субагентов, а не API effort. Он допускается
в архитектурной работе. Общий лимит — два активных помощника, включая AGY и
помощников Ultra. Архитектурному агенту можно явно выделить свободный слот для
ограниченного read-only анализа; его помощник не делегирует дальше. Без такого
слота агент работает последовательно. Один writer на ресурс, один контроллер AE.

## Самостоятельный мост

Общий код находится в отдельном Git-проекте
`C:/Users/Ant/Documents/Codex/agy-bridge`, без отдельного сервиса.
AE Agent обращается к нему напрямую; `config/agy-bridge.json` хранит workspace,
state directory и model/effort. Относительные пути считаются от config файла.
VideoScout использует совместимый запускатель и свою клиентскую конфигурацию.
Python 3.12 доступен как `python`. Запуск из каталога AE Agent:

```powershell
python -X utf8 ..\agy-bridge\scripts\agy_bridge.py --config config\agy-bridge.json run .codex-runtime\my-task.json
python -X utf8 ..\agy-bridge\scripts\agy_bridge.py --config config\agy-bridge.json status my-task-01 --profile ae-agent
```

Пакет содержит `protocol_version: 1`, уникальный `task_id`, `profile: "ae-agent"`,
`kind: "inspect"` или `"edit"`, `instructions`, `original_request`, массивы
`constraints`, `acceptance_criteria`, `allowed_scope`, `material_refs`,
`required_commands`, `required_inputs`, `expected_artifacts`.
Для файлов AE-профиля scope называется `workspace`; пути относительны AE Agent.
Для edit нужен ожидаемый `changed` артефакт в разрешённой области. Полная схема
и пример — в [документации существующего моста](C:/Users/Ant/Documents/Codex/agy-bridge/docs/AGY_BRIDGE.md).
Эта документация нужна диспетчеру для формирования пакета. Назначенный Flash
исполнитель работает с переданными материалами своей задачи; ему не требуется
читать внешний репозиторий моста или повторно выполнять маршрутизацию.
Исходный запрос передавайте дословно в `original_request`; при необходимости
сохраняйте дополнительную файловую копию в `material_refs`. Не сокращайте
обязательные ограничения. Пакет и критерии фиксируются до запуска.

Мост задаёт `--model gemini-3.8-flash-high --effort high`, проверяет каталог
моделей, сохраняет baseline, запрос и полный NDJSON локально в
`.codex-runtime/agy-bridge`. Короткий статус не заменяет независимую приёмку.
Диспетчер отдельно запускает применимые тесты/статические проверки, проверяет diff
и фактический результат. Файловый след сам по себе не доказывает качество.

Монтаж готовых плейсхолдеров группируйте по [рабочему контракту](montage-workflow.md).
В task schema нет `original_request_file`: исходный текст передаётся в
`original_request`, точные дополнительные файлы — в `material_refs`/`required_inputs`.
В финале сверяйте `terminal_result_valid`, `schema_valid`, `artifact_verification`
вместе с transport/task status. Неопределённый транспортный итог сохраняйте;
фактическое выполнение и визуальная приёмка проверяются отдельно.
После поручения использовать [read-only сводку AE Agent](ae-task-completion.md)
с явным списком native run IDs; отдельный запуск модели для её сборки не нужен.

Терминальные проверки исполнителя перечисляйте явно в `required_commands` пакета.
Пустой список заставляет мост запретить shell/terminal даже при существующих
проектных grants. Grants разрешают доступ к команде, а пакет разрешает её запуск
в текущей задаче; одно не заменяет другое. Для live-only поручений без команд
пустой список уместен. В отчёте различайте выполненную проверку и предложенную.

Продолжение — новый task ID и явный `conversation_id` завершённого хода. Никогда
не использовать случайный `--continue`. При timeout сначала status, процесс,
изменённые файлы и pending/read-back; не повторять изменение и не передавать writer
до выяснения исхода. До двух вспомогательных исполнителей суммарно, включая AGY;
они не создают координаторов или субагентов. Один writer на изменяемый ресурс.

## Доступ и ограничения

Codex использует ChatGPT login, Antigravity — существующий аккаунт agy. Провайдеры,
API keys, paid API, покупка кредитов и Terra не включаются. Ultra используется
для архитектурного Sol 6.1; max не является обязательной промежуточной ступенью.
Отсутствующая модель блокирует запуск, без скрытой подмены. При недоступном Flash
разрешено выполнение той же задачи Sol 6.1/high по подписке с записанной причиной и
проверкой, что предыдущий исполнитель остановлен.

MCP Antigravity настроен отдельно через `agy mcp add after-effects` на существующий
адаптер AE Agent. Конфигурация MCP agy общая для аккаунта; отдельный проект
`AE_agent` с 1 октября 2026 года по прямому поручению пользователя имеет постоянные
точные grants для чтения, typed tools, builders, proposal/runner и read-back из
текущего каталога. Они действуют и в следующих задачах этого workspace.
Headless-отказ нового `get_placeholder_protection` устранён и проверен реальным
вызовом Flash. Grants разрешают транспорт, а scope конкретной задачи и gates
bridge определяют допустимое исполнение. Глобальные настройки не менялись.
Границы, расширение каталога и откат: `docs/antigravity-ae-access.md`.

Один контроллер AE. Используйте typed library и прежние plan/dry-run/confirmation/
read-back gates. Не передавайте panel credential внешнему исполнителю. CU — только
необходимый fallback с явной передачей управления; MCP и CU Codex не наследуются
Antigravity автоматически. AE-write этой настройкой не проверяется на рабочем монтаже.
Техническая проверка не является художественным одобрением.
