## Найденные проблемы

### 1. Local Agent planner возвращает пустой plan

С default provider `ollama-local` / `gemma4:latest` панельный Agent на exact JSON prompt вернул:

```text
0 steps, 0 mutating
```

Мутаций тогда не было, cleanup прошел.

Решение уже частично добавлено: deterministic fallback. Если panel Agent plan пустой или неполный, runner должен выполнить тот же exact scenario plan напрямую через backend:

- `/agents/plan/run` dry-run;
- `/agents/plan/run` protected mutating run.

Это нужно записать в Decision Log как QA-решение: fallback валидирует runtime typed tools и checkpoint/edit-session UX, но не меняет product planner behavior.

### 2. Проверка `expectedPanelPlan` сейчас слишком слабая

Второй live run ошибочно принял неполный panel plan, потому что `transcriptIncludesAll(planned.transcript, scenario.expectedTools)` нашел tool names внутри пользовательского exact JSON prompt, а не в реально сгенерированном plan.

Из-за этого render scenario запустил неполный двухшаговый plan:

- создал comp `Codex QA 1.2 47551055 Render`;
- вызвал `add_comp_to_render_queue` без `compName` и без `outputPath`;
- bridge добавил active comp `Slides_fin` в render queue.

Нужно исправить `expectedPanelPlan`, чтобы он проверял именно summary валидации:

- `Validation: ok, <expectedStepCount> steps, <expectedMutatingCount> mutating`;
- `planRunStatus === "Dry run first; Run uses protection"`;
- `planRunStatusClass` содержит `mutating`;
- dry-run/run buttons enabled.

Для этого в `agentScenarioPlans(...).map(...)` добавить:

```js
expectedStepCount: scenario.plan.steps.length,
expectedMutatingCount: scenario.plan.steps.filter((step) => AGENT_SCENARIO_MUTATING_TOOLS.has(step.tool)).length
```

Ожидаемые значения сейчас:

- timeline: 9 steps, 8 mutating;
- layout: 10 steps, 9 mutating;
- source: 8 steps, 7 mutating;
- render: 4 steps, 3 mutating.

Лучше оставить вычисление, не хардкод.

### 3. Остался render queue item от failed run

После второго failed `agent-scenario-smoke` cleanup удалил generated comp, но render queue baseline не восстановился.

По последней проверке render queue:


Логи показывали:

- перед QA baseline был `0`;

Перед следующим live run нужно аккуратно удалить только этот leftover, если guard все еще совпадает:

- `renderQueue.numItems === 1`;
- `renderQueue.item(1).comp.name === "Slides_fin"`;
- нет project items с префиксом `Codex QA 1.2 47551055`;
- удалить только этот item.

Не удалять произвольные render queue items.

## Важные ограничения

- Не запускать QA-сценарии, если active edit session уже открыт.
- Если проект не saved и checkpoint невозможен, mutating сценарии должны остановиться с `save project first`.
- Restore автоматически не запускать.
- Если cleanup/validation падает после мутации, оставить checkpoint path в отчете.
- Удалять только generated items с префиксом `Codex QA 1.2 <stamp>`.
- Для текущего leftover render queue item использовать строгий одноразовый guard, потому что comp уже не generated.
