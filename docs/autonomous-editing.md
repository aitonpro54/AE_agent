# Автономный монтаж через MCP и CEP

Пользователь включает в CEP временную «Автономную сессию Codex». Её capability
`typed_mutating_plan` разрешает серверные типизированные планы после успешного dry-run.
Токен ручного подтверждения не передаётся агенту. Перезапуск daemon не сохраняет lease.

## Цикл выполнения

1. Получить свежую инспекцию точных целей и подготовить план.
2. `propose_ai_agent_plan` проверяет план и связывает его с открытым сохранённым проектом.
3. `run_ai_agent_plan` с `dryRun:true` создаёт receipt для payload, контракта, проекта и всех шагов.
4. Тот же proposal запускается с `dryRun:false` в активной сессии. Сервер проверяет
   полномочия, checkpoint и проект; проверка lease повторяется перед каждой mutation.
5. Независимый read-back сравнивает результат с запросом. Непокрытая проверкой операция
   не получает успешный автономный итог.
6. При допускающем повтор отказе сервер выдаёт `repairDirective`. Исправление — новый
   proposal с `parentActionId`, чтением каждой цели до и после setter и новым dry-run.
   Максимум — две корректировки на исходную цепочку.

`scripts/autonomous-plan-client.js` реализует этот цикл без обращения к LLM-провайдеру.
Исправление ограничено прежними инструментами, полями, точными целями и проектом.
Создание, import, raw JSX и неизвестный результат команды автоматически не повторяются.
После тайм-аута необходимо сначала установить фактический исход read-only инспекцией.
Срок proposal и владелец run повторно проверяются при выдаче queued-команды панели
и перед её `submitted`; уже отправленная AE команда не объявляется отменённой.

## Текущий план в CEP

`get_current_ai_agent_plan` и `GET /agents/plan/current` читают одну серверную запись.
CEP показывает action ID, revision, проект, срок действия, dry-run и результат проверки.
Новый pending proposal заменяет предыдущий. Подтверждённый/выполняющийся план имеет одного владельца;
повторный запрос не меняет его состояние. Старые inline-кнопки отключаются.

Ручной запуск MCP-плана в CEP использует `POST /agents/plan/adopt`: только текущая версия,
идентичность подключённой панели, серверный payload и новый dry-run. Проверка версии
повторяется после асинхронной инспекции. Adoption сохраняет счётчик исправлений.

## Сборка слайд-шоу

`build_slideshow_plan` принимает manifest, статьи и свежую инвентаризацию источников.
Manifest содержит данные: проект, размеры/частоту/длительность, generated prefix,
сцены, заголовки, интервалы медиа, sourceIn, аудио и подписи. Неизвестные поля,
поля кода, перекрывающиеся/разорванные события и неверные диапазоны отклоняются.
Каждый этап содержит не более 50 шагов и независимые проверки результата.

Узкие инструменты клонируют дерево сцены, продлевают generated-слои, переводят ключи
по времени, перепривязывают композиции, оформляют газетный текст, размещают медиа,
сохраняют пары intro/main и CONTROL. Они работают только с точным проектом,
указанными именами и помеченными generated-композициями. Исходные сцены сохраняются.
Индекс элемента проекта меняется при добавлении объектов. Поэтому builder адресует
композиции по уникальному точному имени, а граф копирования использует постоянный `Item.id`.
Явно переданный индекс служит дополнительной проверкой и при несовпадении отклоняется.
Копия слоя определяется по новому `Layer.id`: AE может вставить её после выделенного
слоя. Возвращаемые индексы вычисляются после всех вставок. Если постоянные ID
недоступны, инструмент отказывает до копирования. При переносе ключей interpolation
восстанавливается после temporal ease, поскольку AE иначе меняет LINEAR на BEZIER.
Сокращение сцены меняет границы слоёв без переноса ключей. При продлении больше
`max(2 * frameDuration, 0.07)` переносится только завершающая анимация;
снимок включает соседние неподвижные ключи, которые AE может пересчитать автоматически.
Read-back допускает абсолютную погрешность `1e-4` только у числовых компонентов
пространственных касательных. Длины массивов, остальные флаги и значения проверяются
строго; сравнение ведётся с исходным снимком, чтобы не накапливать дрейф.
`set_comp_properties` управляет motionBlur композиции; `set_layer_metadata` независимо
управляет enabled, motionBlur и audioEnabled слоя.

`build_slideshow_plan` строит данные локально и возвращает `stages`.
`node scripts/slideshow-run-stages.js plan.json` последовательно выполняет эти этапы
через MCP в пользовательской сессии и останавливается при непроверенном результате.

## Ограничения и диагностика

- Raw ExtendScript, destructive tools и direct mutations сохраняют отдельные gates.
- Активная edit session другого проекта вызывает `edit_session_project_mismatch`.
- Выполнение после истечения/отзыва lease останавливается. Уже завершённый шаг не откатывается
  автоматически; checkpoint и журнал позволяют проверить частичный результат.
- Тайм-аут или неизвестный исход нельзя трактовать как отсутствие изменений.
- Read-back ключей ограничен 20 000 записями; усечённый результат не получает успех.
  Плитка конечного footage с собственными ключами отклоняется до изменения дерева.
- Статистика `logs/autonomy-obstacles.jsonl` содержит только время, operation,
  proposal/run ID, код, фазу, длительность, счётчики и статус проверки. Аргументы,
  пути, текст проекта и секреты в неё не включаются. `npm.cmd run report:autonomy`
  показывает сводку. Ошибка записи статистики не скрывает результат исполнения.

## Проверки

`npm.cmd run smoke:autonomy-bridge` проверяет запреты, гонки, проект/checkpoint,
lease, bounded repair и независимый read-back через изолированный daemon/MCP.
`npm.cmd run smoke:slideshow` проверяет данные, emitted JSX, выполнение в модели AE,
негативные read-back сценарии и реальный каталог MCP на отдельном daemon без живого AE.
`node scripts/cep-autonomy-inspect.js` читает реально установленную CEP через CDP и
сравнивает её action ID/revision/project/expiry с MCP; кнопки сессии и запуска не нажимает.
Живая проверка проводится отдельным generated-only fixture после включения lease пользователем.
