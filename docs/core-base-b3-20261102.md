# B3: прекращение прежней работы и новый сеанс

Контракт до production write, 2 ноября 2026; уточнён после единственного Argon
plan review и локального разбора B3-F1–F6/S1. Исходная отправленная редакция
сохранена побайтно в review/context/plan.md. Root — единственный writer и
live-controller. Реализация идёт в существующей installation-scoped композиции;
новый транспорт, Titles compiler и automatic project lifecycle не добавляются.

## Механизм

1. Явная команда «Начать заново» создаёт один durable reset intent с server-owned
   UUID, installation/package/descriptor bindings и точной identity прежнего owner.
   Повтор status/continue относится к тому же UUID. У сброса отдельный синхронный
   запрет физической отправки/выдачи в `/poll`, включая уже принятый pending;
   одного `attachmentOwner.freeze()` недостаточно. Обычный maintenance stop
   сохраняет свою семантику drain; её не менять ради B3.
   Durable reset intent остаётся самостоятельным startup fence до завершения
   сброса, даже если часть старых stores/markers уже перемещена.
   Штатный maintenance stop закрывает owner после завершения его callbacks.
   Ни планы, ни физические команды не переотправляются.
2. Finisher имеет полный installation-контекст и проверяет точную смерть прежнего
   Node producers, свободные канонические IPC/HTTP endpoints и неизменность своего
   intent. Текущий diagnostic owner и прежний active producer учитываются отдельно;
   diagnostic mode не доказывает отсутствия прежнего исполнения AE. При незавершённой
   или неизвестной физической работе он дополнительно требует прекращения всех
   процессов AE, наблюдавшихся после закрытия физического admission при начале
   сброса, и исторических AE producers, если их точные identities доступны.
   Неполная/неоднозначная native observation не принимается. PID без birth не proof.
   Отсутствие stopped.json после crash не блокирует сброс навсегда: допустим
   process-gone-unclean путь с теми же death/endpoint/ownership gates и сохранением
   исходных markers/журналов. Для чистого idle/очереди до submit restart AE не нужен.
   Для submitted/ongoing/UNKNOWN без достаточного durable proof допускается
   консервативное требование AE exit: не вводить aborted_before_delivery и не
   переименовывать UNKNOWN лишь для экономии restart. Новый journal status в
   первом срезе не требуется; судьба исторической команды не угадывается.
   Finisher сам не убивает AE и не закрывает несохранённый проект: показывает
   конкретное необходимое действие. Root защищает работу и выполняет разрешённый
   restart при installed-проверке.
3. После barrier proof и под исключительным файловым допуском finisher сохраняет
   прежние `broker/` и `receiver/` целиком в transaction history, вместе с точными
   runtime/maintenance markers. UNKNOWN остаётся UNKNOWN; manifest отдельно
   обозначает отказ от продолжения прежнего сеанса. Это не success/cancelled,
   не rollback AEP и не ручная очистка locks. Чужие/неатрибутированные markers,
   чужие ресурсы и повреждённые истории не разрешаются по одному имени файла.
   Snapshot изменяемых stores для rename фиксируется после смерти Node writers.
   Intent сохраняет исходный наблюдённый prefix; допустимые completions во время
   drain проверяются как продолжение истории. Нельзя требовать неизменности live
   журнала от intent до stop или принимать заменённую историю. Перед каждым
   rename/продолжением проверяются source/archive identity, bytes/tree digest,
   fixed paths и ownership. Посторонние замены и неатрибутированные стадии
   закрывают продолжение. Fences внешнего writer/shared output не исчезают с
   новым сеансом: ограничения сохраняются либо работа получает точный отказ.
4. Новый сеанс получает новый подписанный session ID, новые Broker/receiver
   stores и owner boot/lease. Старые proposals, tasks, ответы и attachment refs
   отсутствуют в исполняемом состоянии. Все прежние bytes и списки неизвестных
   исходов остаются доступны в reset history. Идентичность установки, credentials,
   origins и пользовательские файлы сохраняются.
   Одна смена owner boot не является достаточным отзывом старого workflow:
   thin client умеет reconnect с той же installation identity. После reset
   новый control допуск требует явного подтверждения текущего server-owned session;
   старый cached session/lease и автоматический reconnect этого не делают.
   Observer status остаётся доступен. Старые queued acquire/run requests без
   нового session binding не должны получать control или возобновлять старый план.
5. Панель принимает session ID только из authenticated handshake. Её старый latch
   сохраняется под прежним session key; новый dispatcher не восстанавливает и
   не исполняет его. Общий для окна dispatcher guard сохраняет незавершённый native
   callback при создании другого dispatcher. Reload CEP сам по себе не proof
   прекращения AE; старые callbacks пишут только свой старый key/channel.
   Новый session не обходит старое исполнение сменой localStorage key.
   До свежей успешной project-inspection этого session ID запрещены build и весь
   путь с эффектами. Baseline-required сохраняется на диске; caller flag или
   inspection другого модуля его не снимают. Сам baseline не выдаёт grants.
   Новая adoption после restart не означает continuity или mutation grant.
6. Фазы intent → stopped/barrier → archive → publish → baseline/ready фиксируются
   до перехода. Любое прерывание оставляет admission закрытым. Один private
   идемпотентный finisher используется штатным запуском и operator continuation;
   вторую реализацию archive/recovery не создавать. Продолжение сверяет
   тот же intent, каждый источник/архив и уже совершённые rename; не угадывает
   промежуточное состояние и не создаёт второй сброс.

## Срезы и файлы

### B3a1 — семантика истории и native process observation

Первый source срез реализован отдельно от writer/production composition:
`runtime/start-over-inspection.js` проверяет receiver/Broker binding, противоречия,
неизменный исходный prefix и допустимые completions во время drain. Новый receiver
begin после fence отвергается. UNKNOWN не переименовывается. Foreign/file/output,
незнакомые schemas и происхождение ресурса без доказуемой локальной AE identity
дают точный отказ; такая исходная граница не исчезает после нового local record.
Точные исторические AE PID/birth сохраняются без потери tick precision.

`runtime/start-over-process.js` даёт фиксированный read-only CIM inventory всех AE
и точную классификацию требуемых прежних Node/AE incarnations одним запросом.
Диагностический owner учитывается отдельно от прежнего writer. PID reuse не
является смертью текущей incarnation. Пустой wire, stderr, missing birth/path,
дубликат, stale observation или ошибка доступа закрывают проверку; public probe/
command override отсутствуют. Результаты этих двух модулей не являются reset
permit, файловым ownership или AE authority.

### B3a2 — durable intent и инспекция запроса

`runtime/start-over-state.js` реализует private owner request: synchronous freeze/
physical-fence callbacks → server-owned intent → fixed native inventory → один
обычный stop request с тем же UUID. Полная installation проверяется до работы;
descriptor, origins, client и adoption закреплены. Подписанные lifecycle markers
атрибутируют отдельно прежнего writer и diagnostic owner; посторонний lock,
несогласованная receiver identity или уже начатый maintenance дают отказ.

Intent публикуется эксклюзивным hardlink только после подготовки полного record
и anchors исходных journal inodes. Повторы возвращают один Promise/UUID, без
повторного stop/native scan. Prefix допускает completion, но не новую physical
команду; старый UNKNOWN и исходные markers сохраняются. Same-bytes replacement
одного/обоих aliases intent либо journal не становится свежим baseline. Ошибка
native probe/записи/stop удерживает опубликованный intent; незавершённые stages
остаются inert evidence. Inspection не заявляет stopped/process-dead/reset-ready.

Private библиотека пока не связана со startup/MCP/CEP/installer. Сами embedding

endpoint/lease barrier, один идемпотентный finisher и архивирование stores с
crash-prefix tests. Затем B3b свяжет startup fence, реальные physical/UI callbacks,
new-session control и baseline. Actual reset/install/save/mutation по B3 остаются0.

### B3a3 — process/endpoint barrier, 3 ноября

`runtime/start-over-barrier.js` резервирует canonical HTTP/IPC endpoints и через
fixed native backend проверяет точные прежние Node/AE incarnations. Private
capability удерживает endpoints и полный snapshot истории/phase до освобождения;
JSON lookalike, drift и потерянный endpoint не заменяют proof. Stopped receipt не
обязателен; факт его отсутствия не переименовывается в clean stop. Shutdown gate
атрибутируется полному прежнему scope, включая role tokens.

При UNKNOWN требуется смерть конкретного AE из исходного inventory и известных
historical origins. Новый AE с другим birth не становится старым producer. Если
owner упал до inventory, после native Node-death записывается один signed
continuation inventory того же intent; последующие попытки проверяют именно эти
births. Если journal risk усилился во время native await, AE set проверяется
заново. Сам barrier не убивает процессы и не выдаёт AE authority/finished reset.

## Адресная приёмка

Очередь до доставки; UNKNOWN и поздний результат; прерывание после каждого
архивирования/публикации; повтор continue того же сброса; чужой PID/birth/marker;
изменённый архив/intent; старый client/proposal/latch; свежая inspection до допуска
эффектов. В component tests допустимы только явно тестовые process observations;
production barriers проверяются штатным native probe без public injection.

После review обязательны: поздний poll после reset fence; diagnostic owner со
старым UNKNOWN; crash до stopped receipt; crash после каждого частичного rename
и после publish; чужие/изменённые source/archive; старый callback при смене session
key; отсутствие/повтор fresh baseline. Проверяется прекращение возможности старого
исполнения, а не вывод отмены команды из смерти Node.

Selector выбирается по фактическому diff каждого среза. Успешные exact closures
переиспользуются; full release и двусторонняя portability не объявляются закрытыми.
Статус: review получен, замечания локально разобраны; B3a1/a2/a3 source приняты.
Полный B3/finisher/production integration ещё не реализованы и не установлены.
Повторный Argon review не требуется.
