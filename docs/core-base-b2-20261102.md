# B2: ожидание и восстановление канала

Минимальный срез после B1: `core4/cep/js/panel.js` и
`core4/test/panel-reconnect.test.js`. Штатный selector выбирает один
`panel-reconnect` batch; остальные изменившиеся integration closures остаются
непроверенными до адресной установленной проверки или отдельного нужного прогона.

## Контракт

- Отсутствие runtime по транспортной ошибке: первые 50 секунд попытки каждые
  3 секунды, затем пауза 15 секунд и новое ограниченное окно. Открытая панель
  продолжает ожидать Core без ручного Connect. Каждый HTTP-запрос ограничен
  timeout; unload прекращает таймер и запрос. Одновременно один цикл.
- `duplicate_peer`: прежний конечный бюджет 50 секунд сохраняется; после него
  пользователь закрывает вторую панель и нажимает Connect. Auth, Origin, pins,
  JSON, HTTP refusal и response MAC не превращаются в транспортные retries.
- Наличие физического latch, UNKNOWN или потеря completion ACK сохраняют
  восстановление original receipt; автоматического нового evalScript нет.
  Таймер подключения не охватывает исполнение AE или native confirmation.
- Клиентский EOF отключает только attachment. `controller_release` освобождает
  lease после завершения принятой работы. `core_disconnect` установленной facade
  сохраняет общий физический канал и возвращает
  `disconnected:false / physical_link_owned_by_installation_owner`.
  Он не заменяет release, остановку owner или отмену команды.

## Проверка

Сохранить существующие negative/replay/fault случаи. Новые проверки: Core появился
после первого окна; длительное отсутствие после idle poll; unload во время
фонового ожидания; latch возник во время ожидания. После установки проверить
видимое состояние панели, configured status и project-inspection. Offline VM
не считается installed/AE proof. B3 «Начать заново» остаётся отдельным механизмом.

Результат2ноября: source реализован, node --check и один selected batch69/69PASS,
git diff --check PASS. Проверки включают production panel/dispatcher в signed
fetch VM и существующие TEMP HTTP callback-loss/ACK cases. Исходный отказ нового
теста выявил ранний переход в backoff на48с; окно исправлено до полных50с и набор
перезапущен успешно. [Evidence](evidence/core-base-b2-20261102.json).
Installedbe9afe99, credentials, AE/CEP и текущая история не изменялись.
