## Почему останавливался AntiGravity

Рассмотрены три задания в `C:/Users/Ant/VideoScout/Code/local/agy-bridge/`.
Имена в таблице — task ID; рядом находятся `.json`, `.ndjson`, `.stderr.txt`.

| Задание | Наблюдение | Вывод |
|---|---|---|
| `ae-slide4-video-review-20260927-01` | Bridge `timeout/unknown`, exit 1, terminal result отсутствует; stderr пустой | Не завершено за 300 секунд; внутренний зависший компонент не установлен. |
| `ae-slide4-shot-map-20260927-02` | `completed/success`, exit 0, непустой структурированный result, 41,95 с | Успешная сверка двух точных JSON manifests. Init подтверждает `gemini-3.8-flash-high`. |
| `huun-watermark-alt-20260928-01` | Bridge `timeout/unknown`; stderr `print timeout after 5m0s with turn in progress`; NDJSON:117 — `SUCCESS`, но пустой response | Частичный result не подтверждает завершение или художественный выбор. |

Первый запуск читал отсутствующие `.packet.json`, корневой README и
`project_code/README.md` (`ae-slide4-video-review-20260927-01.ndjson:32,41,56`).
Watermark-запуск искал отсутствующие metadata/log/packet (`.ndjson:44,47,59`)
и открывал исходные MP4 116–143 MB через `view_file`, который отказал по лимиту
100 MB (`:104,107,110`). Это ошибки путей и способа чтения медиа. Широкий scope
и неудачные чтения правдоподобно расходовали время до timeout; отдельного
доказанного auth/network сбоя здесь нет.

У timed-out заданий `required_commands: []`; подтверждённого permission denial
или `run_command` в этих трассах нет. Увеличение разрешений не устраняет причины.
Код: `Code/scripts/agy_bridge.py:187` (command preflight), `:228` (print-timeout),
`:267` (deadline), `:314` (остановка), `:339` (stderr timeout). Главный чат:
T:439/449, T:648, T:2211/2220.

Shot-map читал `clips_manifest.json` и `selection.json`: пять частей по 2,4 с
и предупреждение о Scene02 на 14,8 с, вне окна 12 с. `artifacts` и
`verified_artifacts` пусты: это успех анализа манифестов, не просмотр видео
и не AE-мутация. В двух других init model отсутствует; приписывать им Flash
или другую модель по умолчанию нельзя.

Часть AGY usage доступна, но отличается по семантике от Codex ledger:

| Result | input_tokens | cache_read_tokens | output_tokens | thinking_tokens |
|---|---:|---:|---:|---:|
| Shot-map, NDJSON:23 | 47 314 | 138 659 | 9 173 | 8 040 |
| Watermark, частичный result NDJSON:117 | 402 640 | 2 689 986 | 15 395 | 11 885 |

Это сырые поля AGY: `total_tokens` равен input+output, не включает cache_read.
Не нормализуем их как Codex cached subset и не прибавляем thinking повторно.
У первого timeout итоговый usage неизвестен. Общая экономия AGY не измерена.

Конкретный рецепт следующего запуска:

1. Проверить существование/размер входных файлов. Один вопрос и точный список
   манифестов, как в успешном shot-map, без обхода произвольных соседних папок.
2. Для визуального вопроса заранее извлечь контактные листы/короткие прокси.
   Проверить поддержку формата выбранным tool: размер <100 MB сам по себе
   ещё не доказывает способность читать видео.
3. Запросить JSON: source IDs, in/out, роль кадра, уверенность и пробелы.
   Анализ материала и применение в AE — отдельные шаги; AE владеет один контроллер.
4. После timeout сначала `agy_bridge.py status <task_id>`, NDJSON/stderr,
   проверка файлов. Новый task ID — только для оставшегося узкого вопроса.
5. Успех: terminal result + корректный непустой JSON + проверенный результат.
   Timeout сохраняет unknown независимо от SUCCESS. Увеличение времени —
   только под измеренную длительность уже ограниченной операции.

Базовый контракт: `Code/docs/AGY_BRIDGE.md:38`. Предлагаемое улучшение драйвера:
preflight входных путей/размеров и отдельные поля transport status, schema validity,
task result, artifact verification. Драйвер/разрешения здесь не менялись;
повторные модельные AGY-запуски не выполнялись.

Рекомендуемый маршрут для обычного старта Sol/high:

1. Готовая короткая операция — родитель вызывает существующий tool/builder.
2. Ограниченная инвентаризация, карта файлов/слоёв или сверка manifest — один
   Luna/high с компактным входом и результатом; два только для независимых тем.
3. Неизвестный tool gap, новый JSX или интеграционная ошибка — Sol/high.
4. Сложный timing/identity/verification конфликт — Sol/xhigh по необходимости.
5. Astra/high — дорогая развилка между подсистемами и границами полномочий.

Передавать child цель, точные файлы/snapshot, запреты, критерий успеха и лимит
ответа. Не копировать весь длинный чат для небольшой разведки. Один контроллер
владеет AE/CEP/UI; другие анализируют неизменяемые снимки. Тайм-аут/auth/unknown
сначала диагностировать, а не лечить повышением reasoning.
При отсутствии явной модели/роли child может унаследовать родительскую;
приоритет model/effort role-file описан в
[официальной документации subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Смета потенциала, а не обещание экономии

Меньшая модель снижает цену токена; это не означает, что она генерирует меньше
токенов. Делегация добавляет prompt, ответ, синтез и иногда повторы.
Computer Use также не отдельная «дешёвая модель»: важны модель контроллера,
число итераций и объём изображений. Один нужный кадр может быть выгоднее
подробного дерева свойств; десятки UI-переходов обычно требуют больше итераций,
чем готовая адресная операция. В этом кейсе A/B-сравнения нет.

Ориентир по опубликованным API Standard short-context ставкам, USD за 1M токенов:

| Модель | Input | Cached input | Output |
|---|---:|---:|---:|
| Luna 6 | 0,10 | 0,01 | 0,50 |
| Sol 6 | 2,00 | 0,20 | 10,00 |
| Astra 6 | 10,00 | 1,00 | 50,00 |

Источники проверены 28 сентября:
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Sol](https://developers.openai.com/api/docs/models/gpt-6-sol),
[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra).
Это не тариф подписки Codex и не формула списания её лимита. Не учитываются
иные tiers, long-context ставки и внешние провайдеры.

Пример небольшого блока с 12k uncached input и 2k output: Sol ≈ $0,044;
Luna ≈ $0,0022. Если делегация добавит родителю 2k uncached input и 1k output,
получится ≈ $0,0162 — на 63% дешевле **этого блока** при равном качестве.
Если добавится ещё 100k cached input родителя, результат ≈ $0,0362,
выигрыш сокращается до 18%. Поэтому краткие поручения полезнее многочисленных
мелких subagents с большим унаследованным контекстом.

| Изменение | Примерная оценка/критерий |
|---|---|
| Убрать 40–80 лишних model responses из похожего 572-response workflow | При прежнем среднем контексте это 7–14% обращений и примерно 5,6–11,3M повторного input. Гипотеза; не доказано, что столько ответов можно убрать. |
| 20–40% подходящего Sol-объёма передать Luna | При одинаковом числе токенов и ставках выше — 19–38% API-эквивалента до overhead; полная задача выиграет меньше. |
| Компактные tool outputs | Измерять доставленные input и число повторных чтений; серверные 8,6M символов не являются готовой оценкой экономии. |
| Sol/high вместо постоянного xhigh | Проверить на одинаковых успешных задачах. Долю reasoning нельзя целиком объявлять устранимой. |
| Предотвратить неверный target и неполный agy submit | Наиболее полезно для качества; процент без повторных сопоставимых задач неизвестен. |

Эти строки пересекаются: складывать проценты нельзя. Реальная экономия
требует одинакового результата и учёта всех retries, children, AntiGravity,
cache и проверки результата.

## Приоритет внедрения и проверка

P0: ограниченный agy-контракт и надёжное распознавание завершения; explicit
target/source/time mapping до AE-плана; сохранять outcome=unknown после
тайм-аута до сверки. Это сокращает переделки без изменения gates.

P1: recipe/builder именно для заполнения готовых Image-плейсхолдеров и
проверки root-time/source-time диапазонов. Общий `build_slideshow_plan` имеет
специализированный article/manifest contract и не является готовой заменой
всего данного задания. Добавить адресный compact read-back и разобраться с
частыми verification failures по сохранённым evidence.

P2: пакет получения проверочных кадров и отдельный AME status/submit adapter.
Не заменять AME status очередью AE; не считать наличие MP4 завершением рендера.
Предусмотреть job identity, preset, destination, range и защиту от duplicate submit.

Для измерения сначала взять 3–5 фиксированных offline/разрешённых fixture-кейсов:
заполнение трёх плейсхолдеров, offset без повторов, split 50/50, получение кадров,
отдельно AME. Сравнить Sol/high без children, Sol/high + Luna/high и прежний
Sol/xhigh при одинаковых критериях качества. Политику cache и все повторные
попытки фиксировать; измерять input/cached/output, время, успех и ручные исправления.
`report:reuse-ab` уже агрегирует сопоставимые задачи; unknown usage остаётся null.
В этом ревью такие live-прогоны не выполнялись.
