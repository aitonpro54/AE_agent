## Как продолжать перенос

1. Передать выбранный commit существующим Git, сохранив локальную работу и истории. AppData, descriptors, credentials, grants, очереди, журналы и пользовательские AEP/assets не импортировать как действующее состояние другой машины.
2. Явно собирать `--composition manual --runtime owner` в новый output, сверять package/standalone closure. Если runtime identity уже установлен и bytes совпадают, повторная установка ради смены компьютера не нужна.
3. Использовать штатный dry-run с обнаружением локальных путей/Node; initial apply — только для новой установки, существующий owner update — по stop/update/inspect/enable контракту. Не чинить пути/порты/tokens вручную.
4. Проверить свежий статус штатного клиента и актуальные module contract/session. Acquire → connect → typed read → release выполнять подряд: lease короткий. UNKNOWN не повторять.
5. После первой установки CEP может потребовать обычного перезапуска AE для обнаружения панели; текущую работу предварительно защитить. На десктопе хватило одного перезапуска без смены версии AE.
6. Новые Core tools были опубликованы как deferred namespace позднее в том же чате; конкретная внутренняя причина не наблюдалась. Перед выводом об отсутствии инструмента повторно сверять свежий inventory; не приписывать успех непроверенному reload.

Постоянный [контракт новых модулей](portability.md#новые-модули-и-последующие-версии) сохраняется: упаковка, локальное обнаружение и адресные проверки затронутых границ выполняются агентом без повторного общего согласования. Этот результат не обещает совместимость всех будущих версий без проверки.
