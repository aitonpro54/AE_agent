# Монтаж по сценам: работа и приёмка

Применять при заполнении готовых плейсхолдеров. Использовать заданные пользователем
сцены и активные варианты. Manifest и отчёты хранить в ignored runtime задачи;
этот документ задаёт рабочий контракт, не заменяет typed tools или AE gates.

## Три основных поручения

1. **Анализ и план шотов.** Один раз проверить исходники, группы и известные
   scene/placeholder identities. Выбрать фрагменты, распределение и план кадров.
2. **Подготовка материалов.** Подготовить согласованные клипы, проверить их
   содержимое, длительность, PAR, кадрирование и сохранённые полные хеши.
3. **Применение и кадрирование.** Выполнить ограниченные typed plans по сценам,
   адресный read-back и исправления. Одно поручение может включать несколько
   proposal/dry-run/run циклов; отдельный запуск Flash на каждый setter не нужен.

Размер блока определяется независимостью работы и ограничениями runner, а не
обязательным числом запусков. Сохранить результат каждого завершённого плана;
`maxSteps` должен охватывать весь рассматриваемый пакет. При частичном результате
продолжать только сверенную оставшуюся работу. Не повторять imports/creation или
неизвестные мутации. Продолжение AGY использует новый task ID и явный conversation
ID завершённого хода; рабочие ограничения передаются заново без потерь.

## Единый manifest до применения

Зафиксировать `schema`, revision, task ID, project identity, observedAt и:

- сцены: stable comp/layer IDs, заданный видимый интервал, fps, существующие
  stretch/remap и маршруты к вложенным/shared композициям;
- назначения: stable placeholder/видеослой IDs, группа, источник и полный SHA256,
  исходные отрезки, времена смен планов и правила position/scale/crop;
- зависимости: какие сцены используют каждый shared placeholder;
- ограничения: принятые ручные правки, защищённые поля, разрешённые повторы и
  недостающие данные; название трека не считать идентификацией исполнителя;
- кадры приёмки: comp ID, root time, проверяемый план/переход, filename и цель
  проверки. Не принимать неизвестные сведения за нулевые значения.

Manifest — описание намерения. Перед записью runner по-прежнему проверяет свежие
идентификаторы, proposal, проект и защиту. Индексы AE не кешировать между
изменениями. После ручной правки, смены проекта или неизвестного исхода обновить
нужный baseline до продолжения; сохранённый receipt не является свежим чтением.

## Инспекция и пакеты кадров

Для плейсхолдеров использовать `get_layer_details(responseView:"placeholder")`.
`evidenceView` не является входным переключателем этого инструмента. Точные
значения/ключи читать через `get_property_value`; полное дерево читать лишь для
конкретного пробела. Канонические native evidence сохраняются целиком на сервере.

Когда runtime поддерживает compact API, выбирать
`run_ai_agent_plan(responseView:"summary")`. Полные детали отдельного результата
получать через `get_plan_run_evidence`; это чтение истории, не read-back из AE.
До обновления runtime использовать поддержанный `full` ответ. Статусы и ошибки
проверять независимо от объёма представления.

План кадров составить до экспорта: начало и последний видимый кадр интервала,
каждый выбранный план, кадры по обе стороны смены плана/кропа и важные движения
камеры. Переводить времена с учётом nested startTime/stretch/remap; для нелинейного
remap нужны наблюдаемые значения. Время кадра должно лежать внутри видимого
интервала, а не точно на исключённой границе outPoint. Убирать точные дубликаты
одной comp/time/state, сохраняя покрытие проверок.

Получать кадры пакетами существующих `save_comp_frame_png` steps. Полный SHA,
bytes/dimensions и завершённость файла вычисляет инструмент, не модель. Просмотр
действительных PNG и проверка читаемости людей/инструментов, случайных пустот,
смен планов и групп остаются обязательной частью визуальной приёмки.

## Проверки после исправления

Исполнитель проверяет изменённые цели. Диспетчер принимает итоговые сцены по
согласованному плану кадров; весь одинаковый промежуточный набор дважды не
пересматривать. Уже просмотренный кадр можно переиспользовать только при той же
идентичности/хеше файла и неизменённом относящемся к нему состоянии.

Изменение источника, timing, crop, свойства, matte/effect или родителя инвалидирует
приёмку этой цели и всех использующих её сцен. Обновить адресный native read-back
и затронутые кадры. При неизвестной области ручного изменения сначала обновить
baseline соответствующих известных сцен. Это не общий кеш проекта и не отмена
серверной свежей проверки перед записью.

При tool blocker сохранить конкретное воспроизведение и выделить инженерное
поручение с одним writer. Продолжать независимую монтажную работу, сохраняя одного
AE/CEP/UI controller. После исправления заново проверить затронутые цели.

## Завершение и измерение

Состояния транспорта AGY, фактических мутаций, технической проверки и визуальной
приёмки независимы. Terminal SUCCESS, файлы на диске и технический PASS не
подтверждают просмотр. `unknown` требует status/process/files/read-back; это не
основание повторить план. Старые ошибочные receipts не переписывать.

На следующем явно порученном монтаже измерять запуски AGY, повторные inspections/
exports, байты ответов, время, documented corrections и записанные input/cached/
output через локальные `get_task_usage`/`get_usage_history`. UUID брать из runtime.
Coverage и timestamps сохранять; отсутствующий usage оставлять неизвестным.
API-эквивалент не считать подписочным счётом, экономию заранее не обещать.

Для изменения этого контракта достаточно offline/config проверок. Клиентский AEP
не менять ради измерений; художественную приёмку проводить в следующем
порученном live scope.
