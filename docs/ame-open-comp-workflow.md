# AME: отправка из открытой композиции

**Статус: краткий черновик; архитектурный контракт ещё предстоит определить.**
Это активное направление для повторной отправки N заданий. Не расширять его
сохранением отдельных AEP, полным SHA AEP или автоматическим fallback.

## Целевой путь

1. Применить visibility только к выбранной цели по текущему поддерживаемому
   workflow и прочитать результат.
2. Использовать композицию, уже открытую в After Effects; подготовить enqueue
   из этого проекта без создания собственного AEP.
3. На каждое новое задание выполнить точное подтверждение нового AME job по
   действующему контракту и зафиксировать его результат.
4. Повторять шаги для N только после завершённого read-back предыдущего задания.

Не использовать полный hash проекта как условие этого пути. Не отправлять batch
молча и не повторять неизвестный submit: сначала reconcile по точному исходному
идентификатору. Автоматический fallback запрещён. START, render и video/output
acceptance в целевой scope не входят.

## Открытые вопросы контракта

- Как привязать visibility read-back к enqueue без сохранения нового проекта.
- Как идентифицировать ровно один новый job, не используя полный queue census.
- Как представить неизвестный результат submit и точное read-only reconciliation.
- Какие существующие per-job proposal, confirmation и self-check gates сохраняются.

До архитектурного решения этот документ фиксирует направление, но не объявляет
его реализованным API или разрешением на live операцию. Экспериментальный
per-title SaveAs/source producer описан отдельно как frozen справочная история:
[AME single-job source workflow](ame-single-job-workflow.md).
