# Usage-телеметрия AE Agent

## Контракт M6

AE Agent показывает два независимых источника:

- `ae-agent-native` — usage конкретных provider-вызовов, наблюдаемых bridge;
- `codeburn_cli` — необязательные агрегаты установленного CodeBurn.

Они не складываются без общего идентификатора дедупликации. Native имеет приоритет
для точного вызова bridge, а CodeBurn остаётся отдельным aggregate-срезом. Отсутствие,
ошибка или timeout CodeBurn не блокируют bridge, очередь или редактирование After Effects.

Квота — отдельный provider/account snapshot. Она не является расходом конкретного
AE-run, стоимостью подписки или model quota без соответствующей гранулярности источника.
API-equivalent dollars показываются вторично и не переводятся в процент подписки.

## Контроль подписки по этапам — 28 сентября 2026

Рабочий первый слой — фактический индикатор аккаунта, полученный через CodeBurn.
Процент относится к конкретному окну лимита (например, неделе), а не к месячной
стоимости подписки. Команды не запускают модель и не требуют открытого AE:

```powershell
npm.cmd run report:quota
npm.cmd run report:quota -- --start montage-01
npm.cmd run report:quota -- --since montage-01
```

`--json` возвращает компактный машиночитаемый результат. Отметки сохраняются
локально в ignored `.codex-runtime/subscription-usage/checkpoints/`, отдельными
файлами без prompts, credentials и account ID. Существующее имя не перезаписывается.
Каждый вызов получает свежую квоту; постоянного polling или фонового агента нет.

Сводка показывает использовано/осталось, окно и сброс, а сравнение — изменение
индикатора в процентных пунктах. Это расход всего аккаунта за интервал. Параллельные
чаты и другие устройства не отделены; identity аккаунта CodeBurn здесь не раскрывает.
Не сравнивать отметки после переключения аккаунта. Изменение плана/окна/reset,
уменьшение индикатора и неверные времена отключают сравнение. Нулевое изменение
не доказывает нулевой расход: остаются округление и задержка провайдера.
Неоднозначные имена или изменение набора окон также отключают численный delta.
Предупреждение исходного снимка сохраняется при сравнении с новым показанием.

Live read-only проверка CodeBurn 0.9.24 выявила `usedPct: 15`, затем `16` в Weekly;
эти показания независимо совпали с `get_usage_limits` Codex. В старом адаптере
alias `usedPct` отсутствовал. CLI также печатал полный JSON, после которого
завершался Windows libuv assertion `UV_HANDLE_CLOSING` в `src/win/async.c`.
Теперь только этот известный случай с полным валидным quota JSON сохраняет
показание со статусом `partial` и явным предупреждением. Произвольные nonzero exit,
timeout, truncation и невалидный JSON по-прежнему не считаются успешным refresh.
Причина падения самого CodeBurn не исправлялась; plugin/npm cache не менялся.

CLI был проверен живыми чтениями; обновлённый CEP source проверен offline.
Установленная панель и работающий daemon не перезагружались этим изменением.

## Локальный ledger конкретной задачи

`npm.cmd run report:task-usage -- --thread current --json` читает локальный Codex
JSONL без модельного вызова. Для дочерних чатов добавьте отдельные `--thread UUID`;
их включение явно видно в `threadIds` и `sessions`. Скрипт суммирует только
`token_usage_record.usage` с уникальным `response_id`, сверяет thread identity,
модель из `turn_context`, целочисленные счётчики и включение cache в input.
Накопительные `thread_token_usage` и UI `token_count` не прибавляются. Содержимое
prompts и ответы инструментов не выводятся и не сохраняются отчётом.

Ledger показывает измеренный объём выбранных чатов по моделям, но пока возвращает
`taskEstimatePercent: null` и `estimateStatus: calibration_unavailable`. Фактический
процент аккаунта запрашивается отдельно через `report:quota`; смешивать эти поля
нельзя. Скрипт читает только явно названные чаты, поэтому пропущенные дочерние
сессии, другие клиенты и вызовы вне Codex могут остаться вне сводки.

## Предлагаемый слой: оценка доли задачи по токенам

Он ещё не реализован: `taskEstimatePercent` в CLI остаётся `null`.
Фиксированной официальной нормы «токенов на 1%» нет. OpenAI прямо разделяет
[кредитные тарифы и включённые лимиты](https://learn.chatgpt.com/docs/pricing).
Для полезной приблизительной оценки нужен эмпирический коэффициент:

1. Сохранять синхронные quota snapshots и приращения usage с response IDs,
   model, cache и speed; не суммировать cumulative snapshots.
2. Взвешивать uncached input, cached input и output по модели/скорости.
   Credit rates могут служить весами, но не знаменателем лимита подписки.
3. На сопоставимых интервалах одного аккаунта, плана и окна оценить
   `k = изменение индикатора, п.п. / взвешенный расход`.
4. Оценку задачи `k × взвешенный расход задачи` показывать отдельно от факта,
   с диапазоном наблюдаемых коэффициентов и числом пригодных интервалов.
   Пока выборка мала — «недостаточно данных», без фиктивного интервала доверия.
5. Исключать reset/смену плана и тарифов, неизвестные модели, неполное покрытие
   других устройств, неподтверждённые speed и пересечение provider aggregates.
   При пропущенных расходах не выдавать локальную долю за точную account attribution.

CodeBurn top-five sessions недостаточно для полного учёта задачи и детей:
для этой части нужен ledger Codex либо расширенный полный export с проверенной
семантикой input/cache. Официальную квоту всегда показывать и без калибровки.
Все вычисления могут быть обычным локальным кодом; дополнительная LLM не нужна.

## Стоимость эксплуатации

Квота и арифметика не вызывают inference; новых платных API или зависимостей нет.
Живой CLI refresh занимал около 3–4 секунд на этом компьютере. Проверка по запросу
или на границе этапа дешевле постоянных модельных опросов. Если пользователь
спрашивает расход в чате, сам ответ Codex расходует обычные токены этого чата;
запуск локальной команды без модели этого накладного расхода не имеет.
Хранение одной отметки — компактный JSON. Долгосрочная поддержка — обновления
формата CodeBurn/лимитов и повторная калибровка после смены плана или моделей.

## Проверенная локальная установка

19 сентября 2026 года read-only проверка обнаружила `codeburn.cmd` версии `0.9.24`.
Команда отчёта:

```text
codeburn.cmd report --provider codex --period week --format json --refresh 0
```

совпала с [документированным full report JSON](https://codeburn.app/docs/json-output):
metadata, `overview`, `daily`, независимые `models` и `projects`, а также ограниченный
`topSessions`. В фактическом обезличенном shape было 5 model aggregates, 3 project
aggregates и 5 top sessions. Эти числа фиксируют только форму локального снимка, а не
полный список сессий и не совместную матрицу model × project.

Read-only `codeburn.cmd quota --format json` завершился успешно, но доступных quota
windows не вернул: 10 provider-status записей, 0 windows. Нормализованный статус —
`partial`, а не нулевая квота. AE Agent не читает и не копирует auth-файлы, cookies или
tokens CodeBurn/Codex. CLI и flags сверены также с
[документацией команд](https://codeburn.app/docs/cli-options) и release `0.9.24`.

CodeBurn не обновлялся. Его internals, UI, optimizer, guard, sync и sharing не
переносились и не включались.

## Runtime

`GET /usage` возвращает только текущий bounded snapshot и не запускает CodeBurn.
`POST /usage/refresh` вручную обновляет недельный report и quota. Refresh использует
фиксированные allowlisted аргументы, корректный Windows `.cmd` launcher, ограничение
времени и объёма stdout/stderr, coalescing параллельных запросов и cache freshness.
Путь CLI можно явно задать доверенной переменной процесса `CODEBURN_PATH`.

Native records имеют versioned allowlist-контракт, bounded in-memory store и
идемпотентный `recordId`. Missing остаётся `null`, а наблюдаемый ноль — `0`.
`cachedInput` и `reasoning` считаются подмножествами input/output и повторно не
прибавляются. Cumulative snapshots не превращаются в increments. Parent/repair calls
сохраняются отдельными provider-call increments; контейнерные или cumulative totals в
их сумму не добавляются.

Codex CLI по-прежнему запускается с `--ephemeral --json`; видимость во внешнем scanner
не является причиной убирать `--ephemeral`. Если rollout отсутствует, CodeBurn source
показывается как отсутствующий/частичный, а не как нулевой расход.

## Гранулярность и privacy

В UI рядом с каждым источником показываются status/freshness и реальная гранулярность.
Model aggregates и project aggregates не соединяются догадкой. `topSessions` всегда
помечается как incomplete top-5. Worktree отображается только при отдельном поле
источника; cwd/project label сам по себе не доказывает точную run attribution.

Нормализованный ответ не содержит prompts, клиентских текстов, абсолютных project
paths, auth data или сырого stderr. Fixtures в `scripts/fixtures/codeburn-usage/`
вымышлены и обезличены. Платные модельные вызовы для проверки M6 не выполняются.
