# Почему рутина оставалась у Sol и что исправлено

Проверено 3 октября 2026 года по инструкциям, конфигурациям и runtime-журналам
чата приёмки `01a100af-21d7-7f13-8f11-76b0d465133b`. Исправление относится к
распределению работы; нового прогона AE или изменения пользовательского AEP нет.

## Причина

Маршрут Luna/Flash был настроен и доступен, но оставался инструкцией диспетчеру.
TOML ролей определяет модель при вызове роли; он сам не назначает её задаче.
В правилах было широкое исключение «готовая проверка/небольшая правка» и фраза
«наличие ролей не означает обязательного запуска». Не требовалось повторно
выбирать исполнителя при переходе от сложной реализации к рутинному сопровождению.
По трассе диспетчер выполнял длинную серию чтений, команд, ожиданий и UI-действий.
Это пропуск применения маршрута, а не подтверждённый отказ запуска Luna.

Выбор модели основного чата ошибочно мог восприниматься как основание оставить
там весь блок. Теперь это явно отделено от прямого указания исполнителя человеком.
Узкие сложные инженерные блоки у Sol остаются допустимыми; их сложность сама по
себе не оправдывает выполнение последующей независимой рутины тем же агентом.

[Документация Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents)
подтверждает доступность subagents по умолчанию и делегирование по прямому запросу
или применимым AGENTS/skill instructions. Отсутствующий явный ключ multi_agent
не является доказательством отключения. Реальные вызовы ниже подтвердили доступ.

## Что показали журналы лонгграна

Основной чат: 524 обращения Sol/xhigh. Помощники по своим runtime metadata:

| Роль | Model / effort | Обращения |
| --- | --- | ---: |
| ae_architect | gpt-6.1-sol / ultra | 26 |
| ae_specialist, root graph | gpt-6.1-sol / xhigh | 110 |
| ae_specialist, canonical integration | gpt-6.1-sol / xhigh | 173 |
| ae_reviewer | gpt-6.1-sol / high | 23 |

Luna в этом чате не вызывалась. Flash выполнял два поручения подготовки и десять
проверочных запусков кадров. Три тяжёлых Codex-помощника получили fork_turns all;
reviewer — none. Для ограниченной рутины полная история теперь исключена по умолчанию.

Независимый подсчёт уникальных token_usage_record по собственным thread_id и
response_id подтвердил **856 обращений Codex**, а не 547. Локальный get_task_usage
не связал три helper threads: дополнительно найдено 309 обращений. Это поправка
предыдущего отчёта; причина неполного импорта Codeburn здесь не исправлялась.
Токены и API-эквивалент не переводятся в точную долю подписочного лимита.

## Исправление

Глобальный AGENTS, проектный AGENTS, docs/model-routing.md и установленный
ae-task-routing теперь требуют выбирать исполнителя каждого самостоятельного
блока и повторять выбор после закрытия сложного блокера. Исключение диспетчеру
ограничено одним готовым коротким вызовом, а не серией проверок и чтений.
Независимые простые evidence/logs/docs blocks идут Luna, средние ясные реализации
AE — Flash. Причины исключений фиксируются кратко; занятые слоты пересматриваются.
Предсказуемое ожидание/парсинг выполняет существующий скрипт без LLM.

Bounded native поручения используют fork_turns none и явно переданные цель,
контекст, ownership и приёмку. Выбор модели чата, роли/effort, providers, grants,
лимит двух helpers, один controller/writer и AE gates сохранены.
Подробности и шесть примеров: [контракт](routine-dispatch-policy.md).

Это обязательный контракт поведения Codex, а не технический перехватчик tool calls.
Один smoke подтверждает доступность и выполнение проверенных поручений, но не
гарантирует безошибочное автоматическое назначение во всех будущих чатах.

| Исполнитель | Поручение и результат | Время |
| --- | --- | ---: |
| ae_scout, gpt-6-luna / medium | Извлечение фактов из routing/config; затем шесть случаев маршрутизации — PASS | 50,4 с + 15,8 с |
| ae_operator, gpt-6-luna / medium | Правка четырёх instruction-файлов по точному контракту; diff принят | 148,8 с |
| Flash, gemini-3.8-flash-high | Создание компактного контракта; файл независимо проверен и уточнён | 52,5 с |

Luna model/effort проверены по turn_context собственных thread IDs; оба bounded
spawn использовали none. Flash effective_model подтверждён; configured_effort=high,
effective_effort=null — отдельного доказательства runtime effort нет.
Flash terminal/schema/artifact checks PASS, tool_error_count=0, процесс завершён.
Поведение шести случаев и повторный выбор после блокера подтвердил scout.

check:rules и diff-check PASS; конфигурации проверяются без вывода credentials.
Штатный quick_validate.py недоступен из-за отсутствующего PyYAML в обоих имеющихся
Python; зависимость не устанавливалась. Frontmatter и ограничения skill проверены
отдельно. Product acceptance/live AE/provider tests для Markdown-правки не запускались.
