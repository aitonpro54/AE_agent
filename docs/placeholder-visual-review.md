# Cover и визуальная приёмка плейсхолдеров

Используется существующий runner с proposal, dry-run, подтверждением и checkpoint/edit-session. Инструменты не создают отдельный исполнитель и не вызывают провайдера автоматически. Пользовательский AEP не сохраняется и не переоткрывается.

`propose_placeholder_cover` читает слой по `{compItemId, layerId}` и геометрию будущего источника по `sourceItemId`. Без ID требуется явный `useCurrentSource:true`. Наблюдаемые subject boxes относятся к source pixels и конкретным изображениям/хэшам. Свободные альтернативы берутся из свежей серверной usage map; клиентская карта не служит доказательством. Результат остаётся предложением, художественная приёмка ожидается отдельно.

Опциональный `framing` у `build_placeholder_plan` использует свежие размеры выбранного будущего источника и frameRate целевой композиции. В план встроены ожидаемые transform/геометрия и отдельный geometry guard. Изменение геометрии перед применением останавливает запись. Anchor сохраняется, scale равномерный. `get_layer_details` и `verify_placeholder_read_back` проверяют фактические значения и четыре границы покрытия. `verify_placeholder_coverage` выполняет самостоятельное чтение текущего слоя. Cover поддерживает статический 2D, square pixels, без parent/rotation/masks/collapse; неизвестные значения, ключи, expressions и separated dimensions не дают успешного результата. Геометрическое покрытие описывает прямоугольный footprint: прозрачность, эффекты и художественное качество требуют просмотра.

`build_placeholder_visual_review_plan({targets})` строит обычный typed plan: `create_placeholder_review_comps`, существующие `save_comp_frame_png` и `get_placeholder_review_manifest`. Не более четырёх целей, 24 временных точек и 24 отдельных видов. Каждая цель задаёт root ID, стабильные target IDs, единственный маршрут, root/target/source time, first/middle/last/shot roles и `viewKinds` (`source`, `target_comp`, `root_comp`). Shared occurrences, stretch/time remap, неизвестные media и устаревшие тайминги явно отклоняются. Один кадр может объединять несколько roles.

Создание добавляет только отдельные служебные композиции. Один контрольный кадр с живой ссылкой имеет `startTime=-sampleTime`, отдельно `inPoint=0`, `outPoint=1/fps`; t=0 остаётся видимым при sampleTime больше кадра. Контроли сохраняют полную нативную рамку, контактный лист использует contain внутри ячейки с отдельной областью подписи. Слои в root/target/main comp не добавляются. PNG экспортируется существующим инструментом только в generated root, на полной resolutionFactor, с восстановлением прежнего значения в finally.

Owner UUID генерирует сервер. ID/name/comment/live sources/timing/transform подтверждаются отдельным actual read-back и сохраняются атомарно в существующем ignored Project Intent runtime `reviewArtifacts`. Comment включает projectKey и owner. Protection/usage исключают только зарегистрированные ID после свежей проверки полного receipt. Prefix, чужой comment или устаревшее содержимое не дают исключения. Native экспорт связывает PNG/header/dimensions/hash со свежим source/time/transform, защищёнными properties и маршрутами; drift до/после экспорта или после capture запрещает выдачу прежнего доказательства. Смена индексов сама по себе fingerprint не меняет.

Манифест содержит непрозрачный SHA256 sourceKey, устойчивые IDs, маршрут, times/roles/viewKind, service ID, PNG paths/hash. Исходный filepath не попадает в компактный манифест. `inspectionMaterials` разбивает target/root controls на детерминированные batches до десяти кадров плюс sheet. Малый legacy запрос сохраняет exact inline manifest и `AE_PLACEHOLDER_REVIEW_PIN:<sha256>`. Canonical запрос использует серверный content-addressed JSON в ignored `.codex-runtime/placeholder-review-manifests`: инструкции содержат exact manifest/file pins и укладываются в6000 символов; required_inputs — JSON, sheet и до10 полных PNG, всего≤12. Для JSON проверяются realpath, полные bytes/SHA и FD identity в пределах1MiB; все существующие родители проверяются до создания каталога. Verify не создаёт заново отсутствующий или изменённый JSON. Inputs относятся к workspace и имеют access `view_file`. Image-only source review не подтверждает target crop. Нечитаемая sheet cell не заменяет обязательный нативный control.

`verify_placeholder_visual_review({owner, inspectionRunIds})` читает только официальные файлы существующего agy-bridge. Legacy `inspectionRunId` поддерживает один batch. Требуются completed/valid inspect/profile/model, парные ACTIVE/DONE `view_file` с совпадающим conversation/step/path, actual PNG/hash и по одному JSON-encoded наблюдению `{frameId, decision:"safe"|"reject", observation}` из официального response.outputs. PNG DONE может не содержать output — это фактически наблюдаемый контракт dispatcher; неизвестный непустой output не считается успехом. Flags модели или клиента и наличие PNG/JSON не заменяют просмотр. Наблюдение должно конкретно описывать людей/головы и границы/отступы; это проверка наличия сведений, а не автоматическое доказательство правдивости текста. Частичные, старые, дублированные batches не дают owner-wide acceptance. Отчёт можно вернуть текстом без обхода запрета записи.

В canonical режиме обязателен также фактический парный JSON `view_file`. Перед
построением view и visual verification сервер проверяет полные current native
capture receipts, графы и contributing files. Компактный view содержит связанные
receipt/graph/file hashes и command/application tuples; сами полные факты остаются
в owner store и immutable native evidence. Canonical owner хранится lossless
`deflate-raw` envelope: physical store≤2MiB, decoded owner≤16MiB, decoded store≤32MiB.
SHA/length/codec/base64 и бюджет распаковки проверяются до обычной полной schema;
corrupt keys/данные никогда не превращаются в пустое успешное состояние.

Удаление выполняется существующим `cleanup_test_items({owner,itemIds,confirm:true})`: exact whole registered set, owner/project/receipt, preflight всех usedIn до undo, запрет внешних dependents, родители раньше детей, finally, отдельная проверка отсутствия ID и только затем unregister. Generic prefix cleanup отклоняет любое пересечение с review prefix. PNG автоматически не удаляются. При частичной ошибке создания/удаления возвращаются фактически известные IDs; мутация не повторяется автоматически. Неуспешно зарегистрированные или неподтверждённые objects требуют отдельной ручной диагностики ownership.

Предел приёмки — предоставленные кадры. Между ними и на неизвестных сменах планов непрерывность не проверена. Источник, тайминг, transform и принятые properties/route защищены fingerprint; произвольные изменения остальных слоёв/effects в root/target не покрываются полным tree hash. Реальный AE render и пользовательский монтаж этим этапом не проверялись; fixtures — actual generated JSX VM и изолированный daemon/fake panel. Тяжёлая face model не устанавливалась. Общие semantic statuses/set_layer_transform recovery относятся к следующему этапу; fit changedCount сам по себе уже не считается geometry proof.
