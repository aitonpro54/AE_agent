# AE Agent Core 4.0.0: намерение и инварианты

Статус: проектирование, 26 октября 2026. [Архитектура](core-4.0.0-architecture.md) и [план M1](../plans/core-4.0.0.md) конкретизируют этот intent. Документы не разрешают реализацию, установку, переключение MCP/CEP или работу с AE.

Решение пользователя от 29 октября 2026 уточняет intent: самостоятельные
workflow-продукты Titles/Slideshow владеют заданиями, шаблонами и compiler вне
Core; отдельно допускаемые AE capabilities владеют ограниченными действиями;
Core сохраняет общий контроль исполнения. Разрешён первый внешний Titles pilot
по [активному плану](../plans/external-products-titles-20261029.md). Исходное M1
ниже сохраняется как минимальный технический срез. Round-trip переносимости
выполняется на финале выбранного функционального состава.

## Намерение

**AE Agent Core** — постоянное название проекта; Core4/4.0.0 обозначает текущий
срез. По поручению пользователя от 28 октября 2026 двусторонняя переносимость
между десктопом и MSI входит в intent всего проекта и сохраняется в следующих
версиях. Разработку крупных архитектурных блоков можно продолжать на любом из
этих компьютеров и возвращать обратно без повторной ручной настройки среды.
Точный контракт, границы локального состояния и критерии готовности —
[«Переносимость AE Agent Core»](portability.md). Это требование, не заявление
уже выполненной реализации или живой приёмки.

4.0.0 — минимальный самостоятельно работающий мост Codex → MCP → typed admission → AE с независимо подключаемыми рабочими пакетами. Ядро обеспечивает связь, управляемость и обязательные ограничения исполнения. Предметные возможности поставляются отдельными версиями и загружаются только по необходимости.

Главный показатель успеха: правка рабочего модуля требует проверки этого пакета и доказанно затронутых взаимодействий. Она не перепривязывает неизменённые компоненты и не требует полного review, MCP reconnect или перезапуска продукта. Проверенные typed operations/builders извлекаются постепенно; переименование прежнего монолита не считается результатом.

Разработка 4.0.0 не зависит от завершения прежнего cutover. Перед будущим живым подключением отдельно устанавливается актуальное состояние реально общих ресурсов и незавершённых отправок. Новая версия не разрешает прежний UNKNOWN.

## Обязательные архитектурные инварианты

1. **Самостоятельный Core.** Startup проверяет только собственную runtime closure. Рабочие пакеты, plan engine и аналитика могут физически отсутствовать.
2. **Предметный код принадлежит модулям.** Builders, handlers, предметные проверки и read-back не становятся «общими primitives» Core. Core не импортирует рабочие пакеты; private-import между соседними модулями запрещён.
3. **Каталог содержит данные.** Discovery не выполняет imports и не хеширует все функции. Generic MCP surface сохраняет стабильные схемы при изменении каталога.
4. **Доверие отделено от схем и hash.** Manifest и совпадение байтов не выдают authority. Только reviewed/admitted executor-артефакт выбранного модуля получает доступ через server-owned admission; worker не передаёт произвольный script.
5. **Gates применяет сервер.** Typed inspection → deterministic build → server-owned proposal → свежий dry-run → подтверждение по риску → read-back сохраняются. Private brands/grants, ownership, checkpoints и shared fences не определяются самим модулем. Raw JSX, destructive и save сохраняют отдельные ручные gates.
6. **Один контроллер отправляет AE-команды.** Модули не имеют transport credentials и прямого CEP доступа. Нейтральный ledger отправок/общих ресурсов живёт независимо от рабочего модуля и plan engine.
7. **Reset не стирает отправку.** Он снимает queued работу и запрещает новые sends этой задачи. Receipt, возможный UNKNOWN и fence остаются; kill worker не доказывает отмену ExtendScript.
8. **Worker сохраняет управляемость Core.** Один процесс запускается по необходимости. Его зависание изолировано от status/reset Core; процесс не является sandbox для враждебного кода под тем же OS user.
9. **Workflow сохраняет частичный успех.** Продолжение выполняет только нужный остаток после адресной сверки. Автоматического атомарного rollback и replay неизвестной мутации нет.
10. **Идентичности локальны.** План закрепляет только реально участвующие компоненты и dependency closure. Изменение постороннего пакета, каталога или чужой записи допуска не переписывает pins плана.
11. **Проверки следуют diff.** Owner, изменённые contracts и обратные зависимости определяют checks с причинами включения. Реально общий API честно затрагивает потребителей. Полная проверка выпуска — отдельное действие.
12. **Evidence ограничена своей областью.** Результат неизменённого artifact сохраняется; он не заменяет свежесть ресурсов, runtime authority или live acceptance.
13. **Пользовательские активы сохраняются.** Обслуживание пакета само по себе не меняет AEP, изображения, текст или outputs. `recordContext` описывает назначение работы, а не полномочия.
14. **Десктоп ↔ MSI без повторной ручной настройки.** Исходники, contracts и пакеты переносимы в обе стороны; локальные paths/config/credentials/state отделены и обслуживаются installer/preflight. После первичной подготовки поддерживаемых сред повторный цикл не требует ручного редактирования исходников, MCP/CEP-конфига, путей или портов. Перенос не создаёт runtime authority и не разрешает replay. Round-trip приёмка на обоих компьютерах обязательна по [постоянному контракту](portability.md), включая для текущего Core4.

Эти требования применяются и к новым, и к постепенно извлекаемым существующим функциям. Нельзя оставлять скрытый доступ к старому монолиту как универсальный fallback.

## Первый срез для решения

Core, optional plan engine, один on-demand worker, `photo-placeholder` и `titles`. Заменить source существующего слоя на уже импортированное still фото, затем изменить текст существующего статичного text layer. Неподдержанные animated/expression/mixed-style случаи отклоняются минимальным контрактом.

Срез должен доказать старт без пакетов, загрузку выбранной closure, независимые pins, локальные проверки, сохранение photo success при titles fault и доступность Core при зависании worker. Измерения A1–A10 приведены в плане. Сейчас продуктовые тесты и live-проверки не выполнялись.
