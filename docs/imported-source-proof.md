# Проверка импортированного видео

`import_footage` для одиночного видео получает независимый серверный read-back
через `find_project_items` по возвращённому stable item ID. Проверка связывает
запрошенный полный путь, ID, тип footage, отсутствие missing footage и строгие
native метаданные результата с новым чтением. Относительные пути разрешаются
от корня bridge; регистр пути нормализуется только на Windows.

Поддержан одиночный видеофайл с положительными width/height/duration/frameRate/PAR
и булевыми hasVideo/hasAudio. Sequence, still, audio-only и неполные либо
противоречивые метаданные остаются `needs_review`. Индекс проекта и basename
не заменяют stable ID и полный путь. Это подтверждение импорта, а не содержания
кадра, личности исполнителя, хэша исходника или художественной приёмки.

Допускается одно серверное чтение, одно явное точное чтение или согласованная
пара этих чтений в окне текущей мутации. Ошибочная целевая попытка, конфликтующая
пара, подделка provenance и дополнительные прикреплённые чтения не дают PASS.
Исторические receipts не переписываются и не повышаются задним числом.

Проверки: `node scripts/semantic-verification-smoke.js` проверяет позитивные
импорты и негативные границы на переносимых fixtures. Опциональный локальный
исторический receipt проверяется только при наличии; отсутствие не мешает
portable suite. Bridge handler добавляет настоящее typed чтение после импорта;
fixture интеграции aggregate сам по себе не доказывает live handler.

На этапе реализации независимые rules, semantic, property identity,
generated safety, PNG proof, syntax и diff checks прошли. Live проверка нового
handler выполняется отдельным разрешённым монтажным этапом.
