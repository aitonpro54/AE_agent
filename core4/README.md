# Core4 M1 — самостоятельный offline-срез

`core4/**` не подключает установленный AE Agent и не импортирует прежний bridge. Node builtins, Node 20+, без install. Один broker, один запускаемый по необходимости worker; engine и рабочие пакеты физически необязательны. Публичный stdio MCP использует bounded NDJSON JSON-RPC. До отдельной интеграции trusted transport/session/grant issuer `connect` возвращает `live_transport_not_installed`. Fake fallback отсутствует.

Команды из корня репозитория:

```powershell
npm.cmd --prefix core4 test
npm.cmd --prefix core4 run check:boundaries
node core4/tools/validate-diff.js core4/modules/titles/implementation.js --run
node core4/core/stdio.js --state-dir C:/Temp/core4-explicit-state
```

`check:release` — отдельная явная проверка нового состава Core4. Она не является default check для локальной правки. `validate-diff` берёт реальный Git diff/untracked paths либо указанные пути и возвращает owner, reason, dependencyPath, concrete command и evidenceKey фактических dependencies. Неизвестный/неоднозначный owner запрещает scoped certification. Keys неизменённой области не зависят от catalog или чужого package. EvidenceKey не выдаёт runtime authority и не заменяет свежесть AE.

Owner/executor tests разделены по `test/modules/*.test.js`; минимальный harness копирует только permanent closure и выбранный package, transport получает explicit selectedModules. Titles-only `--run` проходит при physically absent photo/engine даже в source tree. Titles evidence зависит от выбранной catalog entry, а не от всего catalog или photo tests. Смена public module contract отдельно выбирает `workflow-recovery` с причиной обратной зависимости. Большие integration checks честно закрепляют используемый engine/оба packages.

`checkPolicy` различает независимую component conformance и integration по фактическому содержимому checks. Owner/public-contract/shared-runtime routes обязательны; изменение любой фактической зависимости component check также обязательно выбирает этот check. Поэтому изменение `core/resources.js` включает conformance обоих модулей и shared Core/workflow consumers. Выбор не каскадируется через неизменённые файлы, которые просто читает integration test.

Фактические `checkDependencies`/catalog projections остаются в evidenceKey. Если private-file diff меняет byte closure integration check, но его owner/public/shared contract route не затронут, report явно возвращает `deferredCoverage` со статусом `current-closure-unverified`, changedDependencies, reason и dependencyPath. Deferred closures не открываются и не хешируются; отсутствующий соседний package не становится скрытым условием local conformance. PASS для новой integration closure не заявляется. Исторический результат применим только к своим прежним bytes/dependencies, если такой результат действительно сохранён. Scoped success всегда `releaseCertified:false`.

Private-file diff сам по себе не доказывает семантическую неизменность. Для намеренного изменения поведения без schema diff автор объявляет `selectChecks(paths, root, {contractImpacts:['titles-public-contract']})` либо CLI `--contract-impacts '["titles-public-contract"]'`; соответствующие consumers становятся обязательными. Неизвестный contract ID или owner отклоняется. `--run` объединяет patterns checks одного test file в одну execution batch, сохраняя отдельные причины и evidence keys.

`tools/seal.js` — явная offline упаковка собственных artifacts. Scope обязателен: `--module titles`, `--module photo-placeholder`, `--component engine/core/protocol/worker`; отдельный `--all` нужен только для bootstrap/release. Module scope читает только выбранный module и его public dependencies; чужие manifest/engine/core не читаются и не переписываются. `--reviewed-source` обновляет только выбранные независимые admission records; изменение этих записей требует source review. Сам генератор не является reviewer, PKI или grant issuer. В M1 это records для source review/offline fixtures, не production authorization. По умолчанию startup не запускает packaging и не обходит рабочие packages.

Core `artifacts` читает декларативный catalog, сохраняет prior snapshot при ошибке refresh и проверяет только выбранную closure. Выбранные bytes копируются в content-addressed store и повторно сверяются перед job/send. Admission отдельно связывает operation, input/result schema, effect policy, executor bytes и протокол; отзыв сверяется непосредственно перед send. Core hash содержит только core/worker/protocol. Module pins включают собственный artifact и явно объявленный exact-target contract. Engine pin независим.

Permanent worker тоже запускается из закреплённой копии Core closure; изменение mutable source после startup не подменяет новый child. Перед spawn bytes сверяются снова. Child получает только небольшой OS environment allowlist, без ambient provider/bridge credentials, `NODE_OPTIONS` или `NODE_PATH`.

Worker выполняет admitted local code под тем же OS user: это изоляция event loop, **не OS sandbox**. Guard консервативно запрещает imports/require, Node/global ports и dynamic evaluation у modules/engine. Он сильнее literal-require карты, но не доказывает отсутствие всех возможных JS escape; доверие по-прежнему требует review закреплённых bytes. Core не принимает script/executor paths, claims о resource/effect/grant или `verified:true`. Public API не содержит synthetic issuer, raw JSX, save, destructive или issuance grants.

Публичные tools: `core_status`, `core_connect`, `core_disconnect`, `core_diagnostics`, `list_modules`, `get_module_contract`, `inspect_module_target`, `build_solution_plan`, `propose_plan`, `dry_run_plan`, `run_plan`, `get_task`, `reset_task`, `reconcile_task`. `tools/call` принимает `{name, arguments:{payload:{...}}}`. Contracts выбираются через exact contractId; build с `steps` принимает server evidenceRef, target/desired input, dependencies и ограниченные typed bindings. Proposal создаёт только broker. Confirmation/ownership/checkpoint предоставляет private trusted embedding port, недоступный MCP; единственная реализация issuer в этом срезе находится в `test/fixtures/authority.js` и явно synthetic.

Closed receiver в `core/receiver.js` принимает authenticated protocol/controller/channel/command/executor/payload bindings и только три fixed entry points `inspect/mutate/verify`. Executor bytes provisioned отдельно через private installation seam, не приходят от worker. Реальная CEP доставка не подключена. Fixtures используют этот receiver/codec и actual JSX executor через VM с fake AE APIs.

M2a добавляет independently pinned optional `integrations/cep/`. Core не импортирует пакет; его import не открывает канал, listener, процесс или state. `createTransport({channel,lifecycleProducer})` получает канал только от private embedding: никакого discovery, installed port, credentials fallback или mutation retry. `connect({controllerId,channelEpoch,secret})` provisioned через private capability; это не unauthenticated сетевой handshake. В M2a отсутствует production channel и authoritative lifecycle/grant producer, поэтому standalone connect по-прежнему unavailable. JSON `lifecycleVerified:true` не заменяет private lifecycle brand. Public stdio tools не расширены.

Явный SDK `core/receiver-api.js` предоставляет neutral receiver/protocol interfaces. Private install связывает `moduleId/operationId/executorHash/source/admissionRef` с reviewed admission; immutable host registry сам выбирает asset и fixed phase. В runtime envelope нет executable source/path. Единственный serializer помещает payload в JSON literal, включая quotes, newline и Unicode separators; source-only `CSInterface.evalScript` dispatcher проверен в VM, а не в ExtendScript runtime. Проверка actual ExtendScript JSON/API capabilities остаётся за live-срезом.

Durable completion store требует явно заданную temp/embedding directory. Append+fsync original command binding/digest происходит до evaluate; completion fsync — до reply. Tombstones переживают receiver reopen. Потеря callback, timeout, exception, corruption и storage fault закрывают physical lane; disconnect, timer и отсутствие PID не восстанавливают её. Оставшийся owner marker допускает только proof reads, без автоматического reclaim. Журнал имеет отдельную receiver-store identity, не project-incarnation. Intent Core сохраняет original controller/channel/command/module/operation/executor/payload/phase/store/receipt bindings и transport pin; reconnect не переписывает origin. Каждое новое private подключение Broker получает свежие channel epoch и MAC secret: новый receiver journal отклоняет старый authenticated frame даже при совпавшем CAS baseline. Reconciliation требует continuity того же store, полного original binding и отдельного verify. Legacy intent без origin остаётся UNKNOWN. Secrets в журнале отсутствуют.

Scoped packaging: `node core4/tools/seal.js --integration cep --trace` читает только integration bytes и не меняет Core/module pins. Core/API delta отдельно seal-ится `--component core`. Optional package tests выбираются `node core4/tools/validate-diff.js core4/integrations/cep/transport.js --run`; public receiver/provenance seams выбирают настоящих consumers. Private subject-module changes честно оставляют integration closure в `deferredCoverage`. Offline M2a checks — `node --test core4/test/integration/cep-transport.test.js`: actual fragmented TCP framing/parser, authenticated frames, actual dispatcher source и titles/photo JSX в VM; child crash после intent/physical evaluate/completion, disk write/fsync failures, UNKNOWN/no-replay и new-channel origin. Native AE calls **0**; installed CEP/live/save/reopen не проверены.

`sessionId` означает **project-incarnation epoch**, выпускаемый доверенным наблюдателем AE lifecycle. Любые new/open/revert/replacement, в том числе тот же путь и те же item/layer IDs, обязаны менять epoch. Broker lifetime/channel ID таким epoch не являются. `projectId` дополнительно сверяется с actual `app.project.file.fsName`; unsaved project не поддерживается. Global `AE_CORE_SESSION_ID` допустим только как значение от такого verified producer. Production producer отсутствует; неопределённый lifecycle означает live unavailable.

M2b добавляет только private synthetic `createLifecycleSource({sourceId,sourceEpoch,synthetic:true})`: `apply({sourceId,sourceEpoch,sequence,type,projectId?})`, `snapshot()`, `lose(reason)` и `restart({sourceEpoch})`. Состояния — `unavailable/current/lost`. Последовательность начинается с 1, source/epoch должны совпасть; gap, duplicate/reorder, неизвестное или malformed событие закрывают admission. Потерянный epoch не оживает от reconnect или поздних событий. Restart требует ранее не использованный source epoch и новой project transition. Каждая `project_new/open/revert/replacement` генерирует новый session epoch; unsaved transition меняет epoch, но не выпускает ready binding. Private WeakMap связывает token с текущим поколением source; JSON-копия и старый branded token не проходят проверку. Статический lifecycle-brand bypass удалён. Broker проверяет currentness и exact session/project перед каждым physical send, после получения результата и в продолжениях mutation/reconciliation перед terminal записью. Status и connect fast-path честно показывают потерю lifecycle.

Broker регистрирует у private authority canonical approval: proposal/plan digest, task/epoch и каждый step с module/operation/pins, exact input/target/effect policy и approved snapshot digest. Synthetic `confirm(proposalId)` подтверждает только ранее зарегистрированную запись; `authorize` сверяет весь exact step и актуальный lifecycle, затем сохраняются resource ownership/checkpoint gates. Отзыв или событие source инвалидируют подтверждения. До intent отказ не создаёт receipt; после durable intent, но до отправки, запись может получить definite rejection. После physical send loss/revoke/reset сохраняют original intent/ACK, uncertainty и fence; повторной mutation нет. Успех требует original completion и независимого verify в той же актуальной incarnation. При смерти synthetic observer вместе с child процессом persisted AE values, store и channel не восстанавливают continuity. Отдельная simulation проверяет broker reopen с сохранившимся observer и успешный completion/verify, а replacement observer оставляет старую команду unresolved. Новая incarnation требует свежих proposal и resource/checkpoint bindings.

`npm.cmd --prefix core4 run test:lifecycle` запускает отдельную C1–C6 simulation с реальными Core/worker/receiver/JSX в Node VM, управляемыми send/ACK/readback/microtask границами и **0 native AE calls**. `lifecycle-simulation` имеет собственные owner/contract routes и concrete dependency closure в validation map. Это offline evidence, `releaseCertified:false`; production issuer, реальные AE hooks и installed runtime не реализованы и не проверены.

Photo меняет source одного существующего 2D layer на уже импортированный still FootageItem (`replaceSource(..., false)`), с exact session/project/comp/layer/old/new source и revision CAS. Статичные transform/timing/enable/stretched values защищены independent read-back. 3D/time-remap/animated или expression transform — unsupported. Titles меняет существующий Source Text с exact text/revision CAS, single-line nonempty text, без animation/expression. CharacterRange API появился в ExtendScript AE 24.3; минимум API не доказывает поддержку всех полей на реальном runtime. Каждый символ проверяется по объявленному uniform набору: font/fontSize/fill/stroke/tracking/baseline/scales/fauxBold/fauxItalic, плюс justification/leading/autoLeading. Undefined/range errors/mixed/отсутствующий API — отказ. Сохранение всех неописанных AE style fields не обещается; supported fields сверяются до/после и отдельным verify. Live evidence этого контракта ещё отсутствует.

Нейтральный append+fsync ledger с sequence/hash chain содержит task epochs, ownership/checkpoint/effect/reservation constraints, send-intent, receipt/fence и command identities независимо от worker/engine. Unknown constraint schema сохраняет fence. Единственный процесс владеет state directory; занятый/непонятный owner оставляет diagnostic Core без sends. Torn/short-write/error latch запрещает mutations; intent durable до физической отправки. После crash/ACK loss/read-back failure исход консервативно `UNKNOWN`; reset не стирает receipt. Совпавшее значение не снимает fence: нужно authenticated completion proof исходной команды и независимый read-back. UNKNOWN блокирует новую controller lane и не переигрывается. Journal engine сохраняет workflowId/runId/stepId/attemptId/commandId, partial success и fresh step inspections. Resume проверяет успешный photo на drift и делает только необходимый остаток; command-success fsync до engine journal не теряет успех. Автоматический rollback отсутствует.

Acquire/reclaim/release state ownership сериализуются коротким atomic-wx gate, общим для всех Core4 instances. Сам orphan gate **никогда** автоматически не удаляется: crash в этом критическом участке требует отдельной проверенной ручной recovery; M1 предоставляет диагностику, а не обход. Обычные send/ACK/read-back crash windows допускают reclaim только известного мёртвого PID под gate. `close()` terminal: запрещает новые writes/sends и удерживает lease до завершения running/control/physical promises; поздний old-owner ответ не пишет ledger. Модель не обещает защиту от чужого процесса того же OS user, который игнорирует протокол и меняет файлы.

`recordContext` в новых plan/command records описывает purpose/lifetime/context/project/resources. Default ingress явно `user_work/work_context`; test embeddings задают `technical_check/ephemeral_check`. Назначение не выводится из cwd и не выдаёт authority.

Proposal показывает exact input, expectations, effect, target и pins. Fresh step inspection обязана совпасть с одобренным baseline; она не разрешает молча перезаписать ручную правку. Поздние bindings подтверждают зависимости, но не расширяют одобренную identity. При drift нужен новый inspect/build/propose/confirmation; для продолжения указывается прежний workflowId и стабильные stepId. Новая revision сохраняет совпадающий durable photo success, а изменённый failed titles получает новую попытку. Admission/private grant/resources повторно проверяются непосредственно перед dispatch commit и после задержки между durable intent/send.

Тесты A1–A10 используют production Core/worker/engine/codec/modules и explicit privileged synthetic transport. Crash-window tests действительно завершают отдельный Node broker процесс и открывают его ledger заново; VM setters/receipts хранят synthetic state отдельно. Это offline/VM evidence, native AE calls **0**. Live AE, визуальная проверка, save/reopen AE, installed CEP integration, production grant/session producer и legacy shared-fence census не выполнены. Old authority не импортируется; перед будущим подключением нужен отдельный актуальный разрешённый live-срез.

Все результаты — offline; release/cutover/live acceptance отдельно не запускались.
