# Core4 4.0.0 — отдельный устанавливаемый runtime

Этап I добавляет рабочий внешний Node20+ stdio runtime и отдельную pure-browser CEP-панель `com.codex.aeagentcore4` с меню **AE Agent Core4.0.0**. Runtime запускает HTTP3457 в том же процессе; embedded CEP Node, detached daemon, legacy3456 и зависимости npm не используются. Обычный автоматический lifecycle остаётся unavailable. Ни MCP connect, ни HTTP link не создают project-incarnation.

`runtime/profiles.json` допускает optional `project-inspection` по pinned contract/executor. Existing generic flow `list_modules → get_module_contract → inspect_module_target` возвращает bounded текущую observation: до50 comp summaries и до100 layers выбранной comp. `target:{compId}` необязателен; это discovery saved/unsaved проекта без synthetic session. Observation не выдаёт authority или continuity; build для этого read-only модуля явно unsupported. Остальные generic tools обслуживает существующий Broker с прежними strict gates.

Пакет создаётся детерминированно из `runtime/source-package.json` и закреплённых artifact closures. В пакет не входят tests/experiments/tools/deps/logs/state/`.git`. Fixed JSX registry компилируется при packaging; runtime frame содержит только `assetKey/phase/typedPayload/commandId/originalBinding/pins`. Произвольный source/path/function не принимается. CEP использует native WebCrypto HMAC, fresh challenge/epoch/sequence, отдельный panel token и exact loopback Host/opaque `null` Origin. Недоступный WebCrypto закрывает подключение. JSX registry включает pinned lexical ES3 JSON codec без global polyfill; native JSX JSON не требуется. Native AE APIs требуют фактической live-проверки.

Node append+fsync begin выполняется до публикации команды; complete fsync — до correlated ACK. CEP сохраняет physical latch до eval и callback receipt до POST; latch удаляется только после ACK с exact command/receipt. LocalStorage не является fsync proof: Node store остаётся authority для no-replay. Timeout, callback loss, corruption, reload с потерянным callback и orphan receiver owner закрывают lane. Installer не удаляет owner/fences и отказывает при owned/unknown production state.

Команды подготовки из корня репозитория (первые две не меняют установку):

```powershell
node core4/tools/package-installable.js --output C:/Temp/core4-package.json
node core4/tools/install-core4.js dry-run --package C:/Temp/core4-package.json --node 'C:/Program Files/nodejs/node.exe'
node core4/tools/install-core4.js apply --package C:/Temp/core4-package.json --node 'C:/Program Files/nodejs/node.exe' --expected-package-hash EXACT_HASH_FROM_DRY_RUN
node core4/tools/install-core4.js rollback C:/Users/USER/AppData/Local/AEAgentCore4/transactions/TRANSACTION.json
```

Apply требует exact reviewed package hash и пишет собственный immutable release под `%LOCALAPPDATA%/AEAgentCore4/releases/<packageHash>`, stable state под `state/production`, отдельную CEP extension и только project-local `[mcp_servers.after-effects-core4]` в `.codex/config.toml`. Absolute external Node path/version/SHA256 закрепляются в installation descriptor. Entry загружает только Node builtins до проверки полного release tree: exact file/directory set, включая `release.json`; лишние extensionless files, empty directories, symlinks/junctions и подмена bytes запрещены до любых package imports. Unknown Broker owner, ledger fault и unresolved own intent закрывают физические чтения до нового durable begin, даже если отдельный receiver store пуст.

Stable installation origin и state anchor должны совпадать, reinstall не сбрасывает state. Credentials генерируются вне Git/package, panel/control различаются. Config/descriptor/CEP сохраняются в exact-hash rollback transaction; baseline CAS запрещает перезапись concurrent changes. Bounded TOML editor сохраняет соседние таблицы byte-for-byte, включая indentation и inline comments; неподдерживаемые quoted table headers/multiline syntax отклоняются до записи. Partial filesystem failure оставляет transaction для read-back и ручной диагностики; неизвестная мутация не переигрывается автоматически. Rollback сохраняет production state и release evidence, не восстанавливает живую AE очередь.

Адресная проверка: `node core4/tools/validate-diff.js core4/runtime/stdio-entry.js --run`. Actual-component tests используют настоящий stdio child, HTTP, install/rollback только в test-owned temp и compiled JSX/CEP dispatcher в VM. Native calls0, actual CEP Origin/WebCrypto/JSX API, визуальная панель и установленная live-связь требуют отдельного root-controller evidence.

Этап II добавляет optional `titles-current-target` с target `{projectId,compId,layerId}` и policy `current-matching-target-after-local-confirmation-v1`. Это текущая совпадающая цель, без synthetic session и обещания continuity. Generic flow тот же: `get_module_contract → inspect_module_target → build_solution_plan({oneStep:true,steps:[...]}) → propose_plan → dry_run_plan → run_plan`. Explicit `oneStep` допускает один policy-admitted шаг без engine/dependencies/bindings. Default engine flow и automatic lifecycle-gates прежних модулей сохраняются.

Перед отправкой Broker заново materialize-ит exact одобренный baseline, fsync-сохраняет checkpoint `manual-text-preimage-v1` (точный текст и объявленные style fields, proposal/plan/task/target/effect/pins), получает private branded reservation, повторяет grants/resources/pins/task/cache guards синхронно до send. Это preimage текста, не резервная копия AEP; восстановление требует fresh typed proposal и нового native confirm. В AE confirm показывает путь/IDs и старый→новый текст. После modal boundary executor заново разрешает цель и проверяет text/revision/style, выполняет единственный setter и отдельный local snapshot без Node yield. Success доказывается original durable completion и exact local transaction receipt; later inspect является новой observation и не снимает UNKNOWN. Setter error/readback loss/confirm timeout сохраняют fence/no-replay.

Private `tools/adopt-host.js --installation ABS_DESCRIPTOR --witness ABS_ROOT_WITNESS` выполняет process binding при остановленном runtime под install/start gate. CLI bootstrap загружает только builtins до exact installed-release preflight и descriptor CAS; provider импортируется явным `.js` только из проверенного `releaseDir`, не из mutable operator-relative дерева. Root witness содержит `{installationId,machineId,host:{machineId,aePid,aeProcessBirth,executablePath,executableHash},allowedProject,rootObservationDigest}`. CLI повторно читает actual hostname/CIM process birth/exe hash и named legacy endpoint probes через fixed pinned `windows-host-probe.ps1`; записывает `state/production/host-adoption.json` вне package/Git. Adoption не является mutation grant или epoch. PID/birth не зашиты в source; после нового AE процесса нужен актуальный отдельный bind. Повторная adoption не перезаписывает прежнюю запись автоматически.

Runtime provider заново наблюдает единственный AfterFX процесс и endpoints3456/8787 перед reservation, требует совпадение adopted host и exact allowed project, актуальный state owner/peer/store, отсутствие known conflicts, OS/probe TTL5s и final dispatch TTL2s. Эти TTL не являются world mutex и не освобождают отправленную команду после timeout. v1 same-project UNKNOWN не обходится отсутствием session; known other-machine/process scopes отделены, неизвестные поля не сужают fence. Coverage явно ограничена cooperating Core4 lane, exact adopted host и named endpoints. Legacy physical queue не доказана; другие AE actors вне coverage, shared outputs не запрашиваются. Private brand не восстанавливается JSON-десериализацией. Без adoption run закрыт, inspection/build/proposal доступны.

Discovery display names ограничены256 UTF16 units; serialized observation —40000 units с `truncated:true`, identity не обрезается. Непомещающаяся identity даёт известный `inspection_result_budget` и durable read rejection, без UNKNOWN; следующий корректный read разрешён. Host executor использует ES3 own-key loop. `runtime/host/json-codec.jsx` — локальный data-only recursive descent parser/stringifier с limits262144chars/depth24/nodes32768, duplicate/prototype-key deny, escaping controls/surrogates. Compiled IIFE замыкает executors над lexical `JSON`, wrapper передаёт только serialized data string; native JSON/Object.keys глобалы не нужны и не изменяются. Missing fixed registry даёт known read refusal. Browser/Node продолжают пользоваться native JSON; codec не добавляет executable parser или raw ingress.

Opaque host objects не сериализуются как пустые `{}`. В новом text executor `ParagraphJustification` Enumerator нормализуется только при numeric/string совпадении с явной известной enum constant; неизвестный enum/API закрывает snapshot. Actual AE enum shape и поддержка остальных объявленных style fields остаются live-проверкой.

Адресные suites: `npm.cmd --prefix core4 run test:manual-runtime` и `test:installable`. Они используют synthetic OS observations только через explicit private test composition, actual Broker/worker/HTTP/store/compiled JSX VM; actual Windows process probe/adoption, CEP/WebCrypto/native APIs и mutation на выбранной копии остаются root live acceptance.

Stdio принимает standard optional MCP `params._meta` как bounded8KiB protocol metadata и отбрасывает его до domain dispatch. Это не дополнительный builder/payload/authority input; `arguments` по-прежнему содержит только `payload`.

Production stdio composition даёт человеку100s caller window и90s physical callback window; installer задаёт MCP `tool_timeout_sec = 120`, сохраняя явные existing timeout/enabled preferences. Core/worker defaults и pre-send TTL2s остаются прежними. Callback deadline наступает раньше caller deadline. Timeout не отменяет native окно или уже отправленную команду: поздний ответ не снимает UNKNOWN/fence, повторной mutation нет. Если пользователь явно установил более короткий MCP timeout, он сохраняется и может закончить ожидание раньше host. `test/human-window.test.js` проверяет actual stdio child с delayed synthetic decision >2s и ускоренную physical deadline/no-replay.

Далее сохранён контракт предыдущих offline M1/M2 срезов.

## M1/M2: самостоятельный offline-срез

`core4/**` не подключает установленный AE Agent и не импортирует прежний bridge. Node builtins, Node 20+, без install. Один broker, один запускаемый по необходимости worker; engine и рабочие пакеты физически необязательны. Публичный stdio MCP использует bounded NDJSON JSON-RPC. До отдельной интеграции trusted transport/session/grant issuer `connect` возвращает `live_transport_not_installed`. Fake fallback отсутствует.

Команды из корня репозитория:

```powershell
npm.cmd --prefix core4 test
npm.cmd --prefix core4 run test:repairs
npm.cmd --prefix core4 run check:boundaries
node core4/tools/validate-diff.js core4/modules/titles/implementation.js --run
node core4/core/stdio.js --state-dir C:/Temp/core4-explicit-state
```

`check:release` — отдельная явная проверка нового состава Core4. Она не является default check для локальной правки. `validate-diff` берёт реальный Git diff/untracked paths либо указанные пути и возвращает owner, reason, dependencyPath, concrete command и evidenceKey фактических dependencies. Неизвестный/неоднозначный owner запрещает scoped certification. Keys неизменённой области не зависят от catalog или чужого package. EvidenceKey не выдаёт runtime authority и не заменяет свежесть AE.

Owner/executor tests разделены по `test/modules/*.test.js`; минимальный harness копирует только permanent closure и выбранный package, transport получает explicit selectedModules. Titles-only `--run` проходит при physically absent photo/engine даже в source tree. Titles evidence зависит от выбранной catalog entry, а не от всего catalog или photo tests. Смена public module contract отдельно выбирает `workflow-recovery` с причиной обратной зависимости. Большие integration checks честно закрепляют используемый engine/оба packages.

`checkPolicy` различает независимую component conformance и integration по фактическому содержимому checks. Owner/public-contract/shared-runtime routes обязательны; изменение любой фактической зависимости component check также обязательно выбирает этот check. Поэтому изменение `core/resources.js` включает conformance обоих модулей и shared Core/workflow consumers. Выбор не каскадируется через неизменённые файлы, которые просто читает integration test.

Фактические `checkDependencies`/catalog projections остаются в evidenceKey. Если private-file diff меняет byte closure integration check, но его owner/public/shared contract route не затронут, report явно возвращает `deferredCoverage` со статусом `current-closure-unverified`, changedDependencies, reason и dependencyPath. Deferred closures не открываются и не хешируются; отсутствующий соседний package не становится скрытым условием local conformance. PASS для новой integration closure не заявляется. Исторический результат применим только к своим прежним bytes/dependencies, если такой результат действительно сохранён. Scoped success всегда `releaseCertified:false`.

Private-file diff сам по себе не доказывает семантическую неизменность. Для намеренного изменения поведения без schema diff автор объявляет `selectChecks(paths, root, {contractImpacts:['titles-public-contract']})` либо CLI `--contract-impacts '["titles-public-contract"]'`; соответствующие consumers становятся обязательными. Неизвестный contract ID или owner отклоняется. `--run` объединяет patterns checks одного test file в одну execution batch, сохраняя отдельные причины и evidence keys.

`tools/seal.js` — явная offline упаковка собственных artifacts. Scope обязателен: `--module titles`, `--module photo-placeholder`, `--component engine/core/protocol/worker`; отдельный `--all` нужен только для bootstrap/release. Module scope читает только выбранный module и его public dependencies; чужие manifest/engine/core не читаются и не переписываются. `--reviewed-source` обновляет только выбранные независимые admission records; изменение этих записей требует source review. Сам генератор не является reviewer, PKI или grant issuer. В M1 это records для source review/offline fixtures, не production authorization. По умолчанию startup не запускает packaging и не обходит рабочие packages.

Core `artifacts` читает декларативный catalog, сохраняет prior snapshot при ошибке refresh и проверяет только выбранную closure. Выбранные bytes копируются в content-addressed store и повторно сверяются перед job/send. Admission отдельно связывает operation, input/result schema, effect policy, executor bytes и протокол; отзыв сверяется непосредственно перед send. Core hash содержит только core/worker/protocol. Module pins включают собственный artifact и явно объявленный exact-target contract. Engine pin независим.

Публикация runtime/module CAS требует действующего state owner. Busy Broker читает metadata для диагностики, не создаёт artifacts и не получает worker runtime; `select`/`selectEngine` после busy/close запрещены. Вся closure сначала пишется в собственный уникальный staging-каталог рядом с final: byte count, fsync, close и повторный hash каждого файла проверяются до atomic rename. Existing final только проверяется, повреждение не чинится и не перезаписывается. После process crash orphan staging не используется и автоматически не удаляется; это гарантия видимости complete closure, без заявления о Windows power-loss durability.

Permanent worker тоже запускается из закреплённой копии Core closure; изменение mutable source после startup не подменяет новый child. Перед spawn bytes сверяются снова. Child получает только небольшой OS environment allowlist, без ambient provider/bridge credentials, `NODE_OPTIONS` или `NODE_PATH`.

Worker выполняет admitted local code под тем же OS user: это изоляция event loop, **не OS sandbox**. Guard консервативно запрещает imports/require, Node/global ports и dynamic evaluation у modules/engine. Он сильнее literal-require карты, но не доказывает отсутствие всех возможных JS escape; доверие по-прежнему требует review закреплённых bytes. Core не принимает script/executor paths, claims о resource/effect/grant или `verified:true`. Public API не содержит synthetic issuer, raw JSX, save, destructive или issuance grants.

Публичные tools: `core_status`, `core_connect`, `core_disconnect`, `core_diagnostics`, `list_modules`, `get_module_contract`, `inspect_module_target`, `build_solution_plan`, `propose_plan`, `dry_run_plan`, `run_plan`, `get_task`, `reset_task`, `reconcile_task`. `tools/call` принимает `{name, arguments:{payload:{...}}}`. Contracts выбираются через exact contractId; build с `steps` принимает server evidenceRef, target/desired input, dependencies и ограниченные typed bindings. Proposal создаёт только broker. Confirmation/ownership/checkpoint предоставляет private trusted embedding port, недоступный MCP; единственная реализация issuer в этом срезе находится в `test/fixtures/authority.js` и явно synthetic.

Closed receiver в `core/receiver.js` принимает authenticated protocol/controller/channel/command/executor/payload bindings и только три fixed entry points `inspect/mutate/verify`. Executor bytes provisioned отдельно через private installation seam, не приходят от worker. Реальная CEP доставка не подключена. Fixtures используют этот receiver/codec и actual JSX executor через VM с fake AE APIs.

M2a добавляет independently pinned optional `integrations/cep/`. Core не импортирует пакет; его import не открывает канал, listener, процесс или state. `createTransport({channel,lifecycleProducer})` получает канал только от private embedding: никакого discovery, installed port, credentials fallback или mutation retry. `connect({controllerId,channelEpoch,secret})` provisioned через private capability; это не unauthenticated сетевой handshake. В M2a отсутствует production channel и authoritative lifecycle/grant producer, поэтому standalone connect по-прежнему unavailable. JSON `lifecycleVerified:true` не заменяет private lifecycle brand. Public stdio tools не расширены.

Явный SDK `core/receiver-api.js` предоставляет neutral receiver/protocol interfaces. Private install связывает `moduleId/operationId/executorHash/source/admissionRef` с reviewed admission; immutable host registry сам выбирает asset и fixed phase. В runtime envelope нет executable source/path. Единственный serializer помещает payload в JSON literal, включая quotes, newline и Unicode separators; source-only `CSInterface.evalScript` dispatcher проверен в VM, а не в ExtendScript runtime. Проверка actual ExtendScript JSON/API capabilities остаётся за live-срезом.

Durable completion store требует явно заданную temp/embedding directory. Append+fsync original command binding/digest происходит до evaluate; completion fsync — до reply. Tombstones переживают receiver reopen. Потеря callback, timeout, внешний throw `evalScript`, corruption и storage fault сохраняют UNKNOWN/fence; disconnect, timer и отсутствие PID не восстанавливают очередь. Fixed JSX wrapper ловит отказ executor только в inspect/verify и возвращает private `{readFailureVersion:1,outcome:'rejected',code}` с bounded code. Такой результат либо известный read-only callback `EvalScript error.` до deadline получает correlated durable completion; Broker возвращает ошибку без evidence/success, следующий valid read разрешён. Mutate не получает это исключение, поздний callback после timeout не снимает fence. Оставшийся owner marker допускает только proof reads, без автоматического reclaim. Журнал имеет отдельную receiver-store identity, не project-incarnation. Intent Core сохраняет original controller/channel/command/module/operation/executor/payload/phase/store/receipt bindings и transport pin; reconnect не переписывает origin. Каждое новое private подключение Broker получает свежие channel epoch и MAC secret: новый receiver journal отклоняет старый authenticated frame даже при совпавшем CAS baseline. Reconciliation требует continuity того же store, полного original binding и отдельного verify. Legacy intent без origin остаётся UNKNOWN. Secrets в журнале отсутствуют.

Scoped packaging: `node core4/tools/seal.js --integration cep --trace` читает только integration bytes и не меняет Core/module pins. Core/API delta отдельно seal-ится `--component core`. Optional package tests выбираются `node core4/tools/validate-diff.js core4/integrations/cep/transport.js --run`; public receiver/provenance seams выбирают настоящих consumers. Private subject-module changes честно оставляют integration closure в `deferredCoverage`. Offline M2a checks — `node --test core4/test/integration/cep-transport.test.js`: actual fragmented TCP framing/parser, authenticated frames, actual dispatcher source и titles/photo JSX в VM; child crash после intent/physical evaluate/completion, disk write/fsync failures, UNKNOWN/no-replay и new-channel origin. Native AE calls **0**; installed CEP/live/save/reopen не проверены.

`sessionId` означает **project-incarnation epoch**, выпускаемый доверенным наблюдателем AE lifecycle. Любые new/open/revert/replacement, в том числе тот же путь и те же item/layer IDs, обязаны менять epoch. Broker lifetime/channel ID таким epoch не являются. `projectId` дополнительно сверяется с actual `app.project.file.fsName`; unsaved project не поддерживается. Global `AE_CORE_SESSION_ID` допустим только как значение от такого verified producer. Production producer отсутствует; неопределённый lifecycle означает live unavailable.

M2b добавляет только private synthetic `createLifecycleSource({sourceId,sourceEpoch,synthetic:true})`: `apply({sourceId,sourceEpoch,sequence,type,projectId?})`, `snapshot()`, `lose(reason)` и `restart({sourceEpoch})`. Состояния — `unavailable/current/lost`. Последовательность начинается с 1, source/epoch должны совпасть; gap, duplicate/reorder, неизвестное или malformed событие закрывают admission. Потерянный epoch не оживает от reconnect или поздних событий. Restart требует ранее не использованный source epoch и новой project transition. Каждая `project_new/open/revert/replacement` генерирует новый session epoch; unsaved transition меняет epoch, но не выпускает ready binding. Private WeakMap связывает token с текущим поколением source; JSON-копия и старый branded token не проходят проверку. Статический lifecycle-brand bypass удалён. Broker проверяет currentness и exact session/project перед каждым physical send, после получения результата и в продолжениях mutation/reconciliation перед terminal записью. Status и connect fast-path честно показывают потерю lifecycle.

Broker регистрирует у private authority canonical approval: proposal/plan digest, task/epoch и каждый step с module/operation/pins, exact input/target/effect policy и approved snapshot digest. Synthetic `confirm(proposalId)` подтверждает только ранее зарегистрированную запись; `authorize` сверяет весь exact step и актуальный lifecycle, затем сохраняются resource ownership/checkpoint gates. Отзыв или событие source инвалидируют подтверждения. До intent отказ не создаёт receipt; после durable intent, но до отправки, запись может получить definite rejection. После physical send loss/revoke/reset сохраняют original intent/ACK, uncertainty и fence; повторной mutation нет. Успех требует original completion и независимого verify в той же актуальной incarnation. При смерти synthetic observer вместе с child процессом persisted AE values, store и channel не восстанавливают continuity. Отдельная simulation проверяет broker reopen с сохранившимся observer и успешный completion/verify, а replacement observer оставляет старую команду unresolved. Новая incarnation требует свежих proposal и resource/checkpoint bindings.

`npm.cmd --prefix core4 run test:lifecycle` запускает отдельную C1–C6 simulation с реальными Core/worker/receiver/JSX в Node VM, управляемыми send/ACK/readback/microtask границами и **0 native AE calls**. `lifecycle-simulation` имеет собственные owner/contract routes и concrete dependency closure в validation map. Это offline evidence, `releaseCertified:false`; production issuer, реальные AE hooks и installed runtime не реализованы и не проверены.

Photo меняет source одного существующего 2D layer на уже импортированный still FootageItem (`replaceSource(..., false)`), с exact session/project/comp/layer/old/new source и revision CAS. Статичные transform/timing/enable/stretched values защищены independent read-back. 3D/time-remap/animated или expression transform — unsupported. Titles меняет существующий Source Text с exact text/revision CAS, single-line nonempty text, без animation/expression. CharacterRange API появился в ExtendScript AE 24.3; минимум API не доказывает поддержку всех полей на реальном runtime. Каждый символ проверяется по объявленному uniform набору: font/fontSize/fill/stroke/tracking/baseline/scales/fauxBold/fauxItalic, плюс justification/leading/autoLeading. Undefined/range errors/mixed/отсутствующий API — отказ. Сохранение всех неописанных AE style fields не обещается; supported fields сверяются до/после и отдельным verify. Live evidence этого контракта ещё отсутствует.

Нейтральный append+fsync ledger с sequence/hash chain содержит task epochs, ownership/checkpoint/effect/reservation constraints, send-intent, receipt/fence и command identities независимо от worker/engine. Unknown constraint schema сохраняет fence. Единственный процесс владеет state directory; занятый/непонятный owner оставляет diagnostic Core без sends. Torn/short-write/error latch запрещает mutations; intent durable до физической отправки. После crash/ACK loss/read-back failure исход консервативно `UNKNOWN`; reset не стирает receipt. Совпавшее значение не снимает fence: нужно authenticated completion proof исходной команды и независимый read-back. UNKNOWN блокирует новую controller lane и не переигрывается. Journal engine сохраняет workflowId/runId/stepId/attemptId/commandId, partial success и fresh step inspections. Resume проверяет успешный photo на drift и делает только необходимый остаток; command-success fsync до engine journal не теряет успех. Автоматический rollback отсутствует.

Разрешение дают только полностью совпавшие constraint scopes. Если same-project запись задаёт `itemId/file/output`, отсутствующий в layer target, и известные comp/layer не противоречат target, её ограничения применяются консервативно вместе с broad grant. Такая запись сама broad authority не выдаёт. Известный sibling-layer mismatch сохраняет прежнее исключение; UNKNOWN исходной команды по-прежнему отдельно блокирует проект.

Acquire/reclaim/release state ownership сериализуются коротким atomic-wx gate, общим для всех Core4 instances. Сам orphan gate **никогда** автоматически не удаляется: crash в этом критическом участке требует отдельной проверенной ручной recovery; M1 предоставляет диагностику, а не обход. Обычные send/ACK/read-back crash windows допускают reclaim только известного мёртвого PID под gate. `close()` terminal: запрещает новые writes/sends и удерживает lease до завершения running/control/physical promises; поздний old-owner ответ не пишет ledger. Модель не обещает защиту от чужого процесса того же OS user, который игнорирует протокол и меняет файлы.

`run` и `reconcile` имеют общего exclusive control owner; конкурентный вызов получает `broker_busy`. Completion использует `transportTimeout` для caller, но actual pending promise учитывается до физического settle и продолжает удерживать lease/busy после timeout. Поздний proof не продолжает ledger workflow; после settle нужен новый явный reconcile, original UNKNOWN сохраняется. Status/reset остаются доступны, reset не отменяет уже отправленную команду.

`recordContext` в новых plan/command records описывает purpose/lifetime/context/project/resources. Default ingress явно `user_work/work_context`; test embeddings задают `technical_check/ephemeral_check`. Назначение не выводится из cwd и не выдаёт authority.

Отдельный [offline-прототип локального подтверждения](experiments/manual-current-target/transaction.jsx) исследует policy `current-matching-target-after-local-confirmation`: встроенный `confirm` показывает точные path/compId/layerId и старый/новый текст; подтверждение относится к текущей совпадающей цели, даже после повторного открытия проекта. Это новая semantics, а не continuity исходной incarnation. После modal boundary неизменённый reviewed titles executor заново разрешает цель, сверяет exact text/revision и все объявленные protected style/effect constraints, выполняет единственный setter и local readback; затем factory вызывает отдельный local `verify`. Этот второй snapshot не является независимой верификацией Broker.

Композиция reviewed sources, immutable server-owned proposal registry и direct actual dispatcher/receiver/durable completion доступны только в [private synthetic fixture](test/fixtures/manual-current-target.js), без сети. Registry связывает весь exact proposal/plan/task/step/effect/target/baseline/pins с original controller/channel/command/store; Boolean/callback из payload не подтверждает действие. Durable begin предшествует evaluate; timeout/неопределённый setter остаётся UNKNOWN с original binding, даже если позднее согласие вызовет мутацию. Общий fence экспериментального embedding и durable no-replay не доказывают production shared-lane ownership.

Proposal показывает exact input, expectations, effect, target и pins. Fresh step inspection обязана совпасть с одобренным baseline; она не разрешает молча перезаписать ручную правку. Поздние bindings подтверждают зависимости, но не расширяют одобренную identity. При drift нужен новый inspect/build/propose/confirmation; для продолжения указывается прежний workflowId и стабильные stepId.
